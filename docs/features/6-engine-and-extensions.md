# Engine, files, export, CLI, validation and bundled extensions

Part of the [StarUML feature inventory](README.md); the legend and how to update a status are there.

Source root: `staruml/app/`. Paths below are relative to it. Main menus, keymaps, toolboxes and preferences are in Part 1 and are not repeated here. This part describes the behaviour behind them.

## Application start-up and windows (main process)

- **One window per project** — "New", "New From Template" and "Open" (when the current window already has a file or unsaved changes) each open a *new* BrowserWindow instead of replacing the current project. (src/main-process/application.js:246-258, src/engine/default-commands.js:212-231) — **UMLCraft:** ❌ missing one window only; New and Open replace the project in the same window after the save prompt (src/ui.rs:1618-1631)
- **Open a file from the OS command line** — on Windows and Linux, `argv[1]` of a bundled app is opened as the model file. Without it, the window starts with `loadWorking: true`. (src/main-process/main.js:20-31) — **UMLCraft:** ✅ present any existing `*.mdj` argument is opened on every platform; without one a blank project starts (no "load working" mode) (src/main.rs:167, src/main.rs:202)
- **macOS open-file / dock behaviour** — a file opened through Finder before the app is ready is queued. After that, each one opens a new window. Clicking the dock icon with no visible windows opens an empty window. The app stays alive on macOS after the last window closes and quits on other platforms. (src/main-process/main.js:44-66) — **UMLCraft:** ❌ missing no Finder open-file queue or dock handling; the app quits when its only window closes
- **Start-up file precedence** — (1) the auto-backup file, if the app crashed and `skipLoadBackup` is not set, (2) the `fileToOpen` parameter, (3) the `template` parameter, opened as a new project, (4) the last working file, if `general.working-file` is on and the window was launched with `loadWorking`, (5) otherwise a new project from the default template. (src/app-context.js:688-728) — **UMLCraft:** 🟡 partial only (2) and (5): the command-line file, else the built-in blank project; no backup, template or last-working-file steps (src/main.rs:202, src/app.rs:251)
- **Remember last working file** — each time a project is loaded with a filename, its path is stored (`__working_filename`). "New" clears it. (src/app-context.js:979-982, src/engine/default-commands.js:114) — **UMLCraft:** ❌ missing no last-file memory; nothing is stored between runs
- **Window geometry persistence** — the window's bounds and maximized state are saved under `windowState.main` on every resize, move and close, and restored on the next launch. The default is 1200×900 at (0,0). The window is clamped to the primary display's work area. (src/main-process/window.js:26-94) — **UMLCraft:** 🟡 partial default size 1200×900 only; bounds and maximized state are not saved or restored, no work-area clamping (src/ui.rs:13-14, src/main.rs:186)
- **Hidden title bar on macOS** — on macOS `titleBarStyle: "hidden"`, and the app draws its own title text and drag region. On Windows the title element is removed and the bar is 14px tall. (src/main-process/window.js:114-116, src/views/titlebar-view.js:62-75) — **UMLCraft:** ❌ missing native window decorations on every platform; no custom title bar
- **Window title** — the title is `"• "` (shown when modified), then the file base name, then `" — StarUML"`. It ends with `" (TRIAL MODE)"`, or with `" (TRIAL EXPIRED - VIEWER MODE)"` once the trial has expired. It updates on modify, save, load and license changes. (src/views/titlebar-view.js:34-58, src/app-context.js:926-933, 1513-1515) — **UMLCraft:** 🟡 partial "<file> • — UMLCraft" ("Untitled" when new): the modified mark comes after the name, not as a "• " prefix; no trial suffixes (➖); updates every frame (src/app.rs:304-312, src/ui.rs:1984-1987)
- **Unsaved-changes prompt on window close** — closing a window that has changes opens a native "Save Changes / Do you want to save the changes?" box with Save, Don't Save and Cancel. Save runs `project:save` and keeps the window open. Cancel aborts the close. The renderer reports the modified flag to the main process on every change. (src/main-process/window.js:203-222, src/app-context.js:783-785) — **UMLCraft:** 🟡 partial close with changes cancels the close and shows a native Yes/No/Cancel "Do you want to save changes?" box; but Yes saves and then closes the window instead of keeping it open (src/ui.rs:1889-1898, src/app.rs:382-396)
- **Unsaved-changes prompt on New/Open in the same window** — the same three-button prompt appears. Save saves first, Don't Save discards, Cancel aborts. (src/engine/default-commands.js:124-139, 183-204, src/dialogs/dialog-manager.js:822-837) — **UMLCraft:** ✅ present the same Yes/No/Cancel prompt guards New, Open and Close; Yes saves first (Save As if untitled), Cancel aborts (src/app.rs:382-396, src/ui.rs:1618-1631)
- **Quit saves the working-diagram set** — `application:quit` saves the list of open diagram tabs and then quits. `application:reload` relaunches the app and then quits. (src/engine/default-commands.js:81-93) — **UMLCraft:** ❌ missing Exit just closes the window; open diagrams are not saved anywhere; no reload command
- **Working diagrams (open tabs) persisted per file** — on save, close and quit, the ordered list of open diagram IDs and the current diagram are stored in preferences under `_workingDiagrams.<fullPath>`. They are restored when the file is reopened. (src/ui/diagram-manager.js:152-169, src/app-context.js:984-986, 1017, 1025) — **UMLCraft:** ✅ present on save, on opening another file, on New and on quit, the ordered open diagram ids and the current one are stored under `_workingDiagrams.<fullPath>` in the preferences file and restored when the file is reopened (src/prefs.rs:137-170, src/app.rs:320-323)

(src/app-context.js:987-999) — **UMLCraft:** 🟡 partial only the first diagram with `defaultDiagram: true` (or else the first diagram) is opened; other default diagrams stay closed (src/app.rs:282-286)
- **Deleted diagrams close their tabs** — when a diagram is deleted from the repository (including through undo), its tab is closed. (src/app-context.js:882-887) — **UMLCraft:** ✅ present deleting a diagram drops it from the open list, and undo/redo filters out dead diagrams (src/app.rs:908-911, src/app.rs:402-406)

(src/engine/document-compatibility-resolver.js:25-41) — **UMLCraft:** 🟡 partial `documentVersion` is added on save when missing, but nothing is migrated on load (subject views are not sent to the back; new subject views are inserted at the back) (src/app.rs:335-337, src/canvas.rs:989-995)
- **Fonts loaded at start-up** — the bundled fonts are loaded from `resources/fonts/*/font.json`: Liberation Sans/Serif/Mono as the "default"/"Arial"/"Times New Roman"/"Courier New", plus Gloria Hallelujah, Inter, Lato, Noto Sans, Roboto, Source Code Pro and Source Sans Pro. (src/engine/font-manager.js:84-126) — **UMLCraft:** 🟡 partial missing glyphs fall back to egui's built-in fonts; there are no per-range Unicode (e.g. CJK Noto) fallbacks (src/main.rs:68-77)

(src/app-context.js:629-630, 1520-1522) — **UMLCraft:** 🟡 partial always the dark theme, with colours measured from StarUML's dark CSS; no theme preference (src/main.rs:99-119, src/ui.rs:24-36)

(src/app-context.js:1518-1528) — **UMLCraft:** ❌ missing no preferences; the View › Show Grid checkbox is bound directly to the in-memory flag (src/ui.rs:1187)
- **Native context menus by selector** — the renderer registers context menu templates per CSS selector. The main process builds native menus and pops them up. (src/main-process/context-menu.js:115-148, src/main-process/application.js:281-306) — **UMLCraft:** 🟡 partial egui context menus on Explorer rows and the canvas, built in code (not native menus, no selector registry, no mirrored menu state) (src/ui.rs:258, src/canvas.rs:548, src/canvas.rs:1493-1573)

## Auto-backup and crash recovery

- **Auto-backup every 10 minutes** — while `general.auto-backup` is on, the whole project is serialized to `<userData>/__backup.mdj` every 10 minutes, and its path is recorded in localStorage `__backup_filename`. (src/app-context.js:91, 1533-1553) — **UMLCraft:** ❌ missing no auto-backup
- **Clean exit clears backup marker** — `window.onbeforeunload` removes `__backup_filename`, so the backup is offered only after an abnormal exit. (src/app-context.js:809-811) — **UMLCraft:** ❌ missing no backup marker
- **Crash recovery on launch** — if the marker exists and the file is present, a red toast "App was unexpectedly terminated. Auto backup file has loaded." appears. The backup is loaded as an untitled project (no filename), marked modified, and the backup file is deleted. New, New-from-template and Open windows skip this (`skipLoadBackup`). (src/app-context.js:697-708, src/main-process/application.js:246-258) — **UMLCraft:** ❌ missing no crash recovery

Focus moves to the canvas first so a pending documentation edit is committed. The modified flag is cleared. (src/engine/default-commands.js:148-175, src/engine/project-manager.js:126-145) — **UMLCraft:** 🟡 partial tab-indented JSON to the current file, or Save As when untitled; the dialog suggests "<project name>.mdj" and has only the "Models" filter (no "All Files"); any other extension is replaced by `.mdj`; modified flag cleared (src/app.rs:340-379, src/model.rs:155-162)

(src/engine/default-commands.js:183-234, src/engine/project-manager.js:152-175, src/app-context.js:972-1010) — **UMLCraft:** ✅ present "Open Model" dialog with Models and All Files filters; a failure shows "Failed to open the file." with the error; loading clears undo/redo and selection and expands the root and its children (src/ui.rs:1624-1631, src/app.rs:314-319, src/app.rs:271-302)

## Diagram image export (PNG / JPEG / SVG)

- **Export current diagram as PNG/JPEG/SVG** — a Save dialog opens with default name `filenamify(diagram.name || "diagram")` plus `.png`, `.jpg` or `.svg`. "No diagram to export." appears if no diagram is open. The selection is cleared before rendering. (src/engine/default-commands.js:360-445, src/engine/diagram-export.js:233-265) — **UMLCraft:** ✅ present PNG, JPEG and SVG; the Save dialog proposes filenamify(name or "diagram") with .png, .jpg or .svg; the selection is cleared first; with no diagram open the toast "No diagram to export." appears (src/ui.rs:1679-1694, src/export.rs:34-68)
- **Raster export geometry** — the image is cropped to the bounding box of all views including children, expanded by 10px, plus 30px of extra canvas width and height, at zoom 1. It is scaled by `devicePixelRatio`, so HiDPI screens produce 2x images. (src/engine/diagram-export.js:106-128) — **UMLCraft:** 🟡 partial bounds of top-level views (node boxes and edge points) + 10px margin + 30px extra, zoom 1, scaled by pixels-per-point; edge labels and sub-views are not part of the bounding box (src/render.rs:346-368, src/render.rs:428-465)
- **PNG keeps transparency, JPEG gets white** — only JPEG export fills the canvas with `#ffffff` first. (src/engine/diagram-export.js:130-134) — **UMLCraft:** ✅ present PNG has a transparent background; JPEG is flattened on white (src/export.rs:42-61)
- **SVG export** — rendered through `svgcanvas` to the bounding box plus 10px. External `file://` PNG and SVG images are inlined as base64 data URIs. (src/engine/diagram-export.js:57-97, 178-224) — **UMLCraft:** ✅ present SVG cropped to the bounding box + 10px, no extra; there are no image views, so nothing to inline (src/render.rs:433-450)
- **Export All Diagrams to PNGs/JPEGs/SVGs** — pick a folder (the dialog can create one). The command creates the subfolder `<folder>/<png|jpg|svg>/` and writes every Diagram in the repository as `filenamify(diagram.getPathname()) + "_" + index + "." + ext`. (src/engine/default-commands.js:452-535, src/engine/diagram-export.js:275-298) — **UMLCraft:** ✅ present pick a folder; every diagram is written to `<folder>/<png|jpg|svg>/` as `filenamify(path)_<index>.<ext>`, the path joining the owners' names with "::" (src/ui.rs:1697-1710, src/export.rs:73-98)
- **Copy Diagram as Image** — the current diagram is put on the system clipboard as an image: PNG on macOS, JPEG elsewhere. (src/engine/default-commands.js:678-700) — **UMLCraft:** ✅ present the current diagram goes to the system clipboard as a picture, with a white background outside macOS (the original uses JPEG there) (src/clipboard.rs:162-195)

## Command-line interface (`staruml <cmd>`)

- **CLI mode** — triggered when the first argument is one of `ejs`, `image`, `html`, `pdf` or `exec`, or by `--help`/`--version`. The model opens in a hidden window, the command runs 2.1s after app-ready (to let fonts load and the license validate), and the app quits 500 ms later. Output goes to the main-process console. ## UML text grammars (inline edit, PEG.js) and how they are applied

- **Name expression** `<<stereotype>> [+|#|-|~]name`: sets the name and the visibility (+ public, # protected, - private, ~ package). The stereotype is looked up by name as a UMLStereotype from the element's scope. If it is found, a reference is set. If not, the stereotype is stored as a plain string. Omitting the stereotype clears it. (uml/grammars/uml-name.pegjs; uml-commands.js:288) — **UMLCraft:** ✅ present `<<stereotype>>` (or `«stereotype»`) and the visibility sign are parsed; a UMLStereotype of that name anywhere in the project is linked, otherwise the text is stored; no stereotype clears it (src/parse.rs:19-66; src/canvas.rs:1291-1295)
- **Attribute expression** `<<st>> vis name : type [mult] = default`: the type is resolved to a UMLClassifier by name, or kept as a string if not found. Multiplicity takes only digits, `.` and `*`. Any part left out is reset: type becomes null, multiplicity and default become "". (uml/grammars/uml-attribute.pegjs; uml-commands.js:331) — **UMLCraft:** ✅ present stereotype, visibility sign, `/` derived, name, `: type`, `[mult]` and `= default` are parsed and left-out parts reset (type removed, multiplicity/default ""); the type is linked to a classifier of that name, else kept as a string. Multiplicity characters are not restricted (src/parse.rs:87-121)
- **Operation expression** `<<st>> vis name(in|out|inout p : T [m] = d, ...) : ReturnType [m]`: the whole edit runs as one undoable "change operation". Existing parameters are updated in place by position, extra ones are created and surplus ones are deleted. A parameter with no direction defaults to `in`. A return parameter is created, updated or removed to match the return type. Leaving out the parentheses removes all parameters. (uml/grammars/uml-operation.pegjs; uml-commands.js:398) — **UMLCraft:** ✅ present one undo step; stereotype, visibility, name, `in`/`out`/`inout` (default `in`), `: T [m] = d` per parameter, updated in place by position with extras created and surplus deleted; the return parameter follows the return type; no parentheses removes every parameter. The return multiplicity is not read (src/parse.rs:123-184)
- **Template parameter expression** `<<st>> name : type = default`: sets `parameterType` (a string) and `defaultValue`. (uml/grammars/uml-templateparameter.pegjs; uml-commands.js:622) — **UMLCraft:** ❌ missing no template parameters
- **Object (instance) expression** `<<st>> vis [name] : Type`: the name is optional. Type is resolved and set as the `classifier`. (uml/grammars/uml-object.pegjs; uml-commands.js:1720) — **UMLCraft:** ❌ missing no object diagrams
- **Slot expression** `<<st>> vis name : type = value`: sets the slot's name, type and value. (uml/grammars/uml-slot.pegjs; uml-commands.js:1773) — **UMLCraft:** ❌ missing no slots
- **Lifeline expression** `<<st>> vis name [selector] : Type`: sets the lifeline's name and selector. (uml/grammars/uml-lifeline.pegjs; uml-commands.js:2106) — **UMLCraft:** ❌ missing no lifelines
- **Message expression** `<<st>> target = name(arguments)`: sets `assignmentTarget`, name and `arguments` (one raw string). Missing parts are cleared. (uml/grammars/uml-message.pegjs; uml-commands.js:2478) — **UMLCraft:** ❌ missing no messages

(uml/grammars/uml-attribute.pegjs) — **UMLCraft:** ✅ present the parser splits on punctuation only, so names with spaces, CJK and `List<T>` types are accepted (a comma inside a parameter type such as `Map<K,V>` splits the parameter) (src/parse.rs:68-83, src/parse.rs:140)
