# Engine, files, export, CLI, validation and bundled extensions

Part of the [StarUML feature inventory](README.md); the legend and how to update a status are there.

Source root: `staruml/app/`. Paths below are relative to it. Main menus, keymaps, toolboxes and preferences are in Part 1 and are not repeated here. This part describes the behaviour behind them.

## Application start-up and windows (main process)

- **One window per project** — "New", "New From Template" and "Open" (when the current window already has a file or unsaved changes) each open a *new* BrowserWindow instead of replacing the current project. (src/main-process/application.js:246-258, src/engine/default-commands.js:212-231) — **UMLCraft:** ✅ present every window is a process of its own: File › New and New From Template start another UMLCraft with `--new-window` (the original's skipLoadBackup), and Open, Open Recent and a dropped file open in a new window when this one already has a file or changes, else here (src/window.rs:238-264, src/window.rs:90-107; src/ui.rs:2381, 3193-3222). The windows share the preferences file: each writes only the keys it changed over the file as it is now (src/prefs.rs:60). Deliberate difference: Exit (Ctrl+Q) closes this window only, as the processes know nothing of each other
- **Open a file from the OS command line** — on Windows and Linux, `argv[1]` of a bundled app is opened as the model file. Without it, the window starts with `loadWorking: true`. (src/main-process/main.js:20-31) — **UMLCraft:** ✅ present any existing `*.mdj` argument is opened on every platform; without one the window starts in "load working" mode (src/window.rs:58-85, 180-197)
- **macOS open-file / dock behaviour** — a file opened through Finder before the app is ready is queued. After that, each one opens a new window. Clicking the dock icon with no visible windows opens an empty window. The app stays alive on macOS after the last window closes and quits on other platforms. (src/main-process/main.js:44-66) — **UMLCraft:** 🟡 partial on Windows and Linux the app quits when its window closes, as the original. On macOS a file opened from Finder is not received (winit 0.30, under eframe, reports no open-file event), clicking the dock icon does not reopen a window, the app quits with its last window, and each window shows its own dock icon (src/window.rs:1-8)
- **Start-up file precedence** — (1) the auto-backup file, if the app crashed and `skipLoadBackup` is not set, (2) the `fileToOpen` parameter, (3) the `template` parameter, opened as a new project, (4) the last working file, if `general.working-file` is on and the window was launched with `loadWorking`, (5) otherwise a new project from the default template. (src/app-context.js:688-728) — **UMLCraft:** ✅ present the original's order: the auto-backup after a crash unless another window opened this one, then the file, then `--template <name or file.mdj>` as a new project, then the working file when `general.working-file` is on and the app was launched without a file, else a new project, which forgets the working file (src/window.rs:58-85, 180-208; src/main.rs:205, 261-268)
- **Remember last working file** — each time a project is loaded with a filename, its path is stored (`__working_filename`). "New" clears it. (src/app-context.js:979-982, src/engine/default-commands.js:114) — **UMLCraft:** ✅ present each project opened from a file is stored as `__working_filename` in the preferences; a new project (New's window, or a launch with nothing to open) clears it (src/app.rs:458-470; src/prefs.rs:703-712; src/window.rs:202-208)
- **Window geometry persistence** — the window's bounds and maximized state are saved under `windowState.main` on every resize, move and close, and restored on the next launch. The default is 1200×900 at (0,0). The window is clamped to the primary display's work area. (src/main-process/window.js:26-94) — **UMLCraft:** ✅ present the bounds and maximized state are kept under `windowState.main` in the preferences whenever they change and restored at the next launch, negative coordinates becoming 0; the default is 1200×900. On the first frame the window is made no larger than its screen and its right and bottom edges are pulled onto it (src/main.rs:221-238; src/ui.rs:3804-3820; src/window.rs:162-176, 298-318). Deliberate difference: the egui screen is the one the window opens on, and a window lying beyond it (on a second monitor) is left there
- **Hidden title bar on macOS** — on macOS `titleBarStyle: "hidden"`, and the app draws its own title text and drag region. On Windows the title element is removed and the bar is 14px tall. (src/main-process/window.js:114-116, src/views/titlebar-view.js:62-75) — **UMLCraft:** ✅ present on macOS the system title bar is hidden (full-size content view) and UMLCraft draws a 28px bar with the window title in the middle, room for the traffic lights, drag to move and double-click to zoom; elsewhere the system title bar stays, as on Windows and Linux in the original (src/window.rs:148-159, 334-351). Not tried on a Mac here
- **Window title** — the title is `"• "` (shown when modified), then the file base name, then `" — StarUML"`. It ends with `" (TRIAL MODE)"`, or with `" (TRIAL EXPIRED - VIEWER MODE)"` once the trial has expired. It updates on modify, save, load and license changes. (src/views/titlebar-view.js:34-58, src/app-context.js:926-933, 1513-1515) — **UMLCraft:** ✅ present "• " when modified, then "<file name> — " when there is a file, then "UMLCraft"; no trial suffixes (➖); updated every frame (src/app.rs:432-437, src/ui.rs:3109-3112)
- **Unsaved-changes prompt on window close** — closing a window that has changes opens a native "Save Changes / Do you want to save the changes?" box with Save, Don't Save and Cancel. Save runs `project:save` and keeps the window open. Cancel aborts the close. The renderer reports the modified flag to the main process on every change. (src/main-process/window.js:203-222, src/app-context.js:783-785) — **UMLCraft:** ✅ present closing a window with changes cancels the close and shows the native "Save Changes" / "Do you want to save the changes?" box: Save saves and keeps the window open, Don't Save closes it, Cancel keeps it (src/window.rs:118-145, 270-292)
- **Unsaved-changes prompt on New/Open in the same window** — the same three-button prompt appears. Save saves first, Don't Save discards, Cancel aborts. (src/engine/default-commands.js:124-139, 183-204, src/dialogs/dialog-manager.js:822-837) — **UMLCraft:** ✅ present New and New From Template always open a new window, and Open does when this window has changes, so the project is never replaced with changes pending; the same Save / Don't Save / Cancel prompt guards the window's close and the StarUML 1 import (src/window.rs:118-145, 250-257; src/app.rs:531-549)
- **Quit saves the working-diagram set** — `application:quit` saves the list of open diagram tabs and then quits. `application:reload` relaunches the app and then quits. (src/engine/default-commands.js:81-93) — **UMLCraft:** ✅ present closing the window (Exit included) saves the open diagrams and the current one for the file, and they reopen with it (src/window.rs:280; src/prefs.rs:181); `application:reload` (command palette id, keymap.json) closes the window and starts UMLCraft again with the same arguments once it has closed (src/palette.rs:351-354; src/window.rs:110-117; src/main.rs:273)
- **Working diagrams (open tabs) persisted per file** — on save, close and quit, the ordered list of open diagram IDs and the current diagram are stored in preferences under `_workingDiagrams.<fullPath>`. They are restored when the file is reopened. (src/ui/diagram-manager.js:152-169, src/app-context.js:984-986, 1017, 1025) — **UMLCraft:** ✅ present on save, on opening another file, on New and on quit, the ordered open diagram ids and the current one are stored under `_workingDiagrams.<fullPath>` in the preferences file and restored when the file is reopened (src/prefs.rs:157-191, src/app.rs:442-446)
- **Default diagrams auto-open** — on load, every diagram with `defaultDiagram === true` is opened, and the first one becomes current. (src/app-context.js:987-999) — **UMLCraft:** ✅ present every diagram with `defaultDiagram: true` opens in Working Diagrams and the first becomes current; with none, the first diagram opens (src/app.rs:390-394)
- **Deleted diagrams close their tabs** — when a diagram is deleted from the repository (including through undo), its tab is closed. (src/app-context.js:882-887) — **UMLCraft:** ✅ present deleting a diagram drops it from the open list, and undo/redo filters out dead diagrams (src/app.rs:1709-1712, src/app.rs:530-534)
- **Document version migration** — a project with `documentVersion < 1` is migrated on load. All `UMLUseCaseSubjectView`s are sent to the back, and `documentVersion` is set to the current value. (src/engine/document-compatibility-resolver.js:25-41) — **UMLCraft:** ✅ present a project with `documentVersion` below 1 (or none) has every UMLUseCaseSubjectView sent to the back of its diagram on load, and `documentVersion` set to 1 (src/app.rs:381, 415-430)
- **Fonts loaded at start-up** — the bundled fonts are loaded from `resources/fonts/*/font.json`: Liberation Sans/Serif/Mono as the "default"/"Arial"/"Times New Roman"/"Courier New", plus Gloria Hallelujah, Inter, Lato, Noto Sans, Roboto, Source Code Pro and Source Sans Pro. User fonts are loaded from `<userData>/fonts/<dir>/font.json`. (src/engine/font-manager.js:146-202, src/app-context.js:625-626) — **UMLCraft:** 🟡 partial the faces StarUML lists (Gloria Hallelujah, Inter, Lato, Arial, Times New Roman, Courier New, Roboto, Source Code Pro, Source Sans Pro, Helvetica, Times, Courier) are offered, and each is found among the system's fonts when a view first uses it, with Liberation, Arimo/Tinos/Cousine or Nimbus standing in for Arial, Times New Roman, Courier New and the PDFKit faces; user fonts come from `fonts/<dir>/font.json` next to the preferences file (src/fonts.rs:21, 38-75, 108-151, 231-306). UMLCraft bundles no fonts, so a face not installed draws with the Arial-compatible one
- **Unicode fallback fonts** — a "default" font that has `unicodeRanges` is used for the characters in those ranges, for example CJK through Noto. A named font that does not cover a character falls back to the default font for that range. (src/engine/font-manager.js:84-126) — **UMLCraft:** ✅ present a face without a character falls back to the Arial-compatible face, then to CJK system fonts: the first text with CJK characters loads, for 中, あ and 한 in turn, a font that has it (Noto Sans CJK SC/JP/KR, Microsoft YaHei, PingFang, WenQuanYi, …), for the diagram faces and the panels; a CJK system language loads them at start-up. The user's "default" fonts are fallbacks of every face. The PDF falls back the same way (src/fonts.rs:176-229, 310-369; src/pdf_font.rs:149-178)
- **User fonts become CSS @font-face** — non-predefined user fonts are injected as `@font-face` rules for regular, italic, bold and bold-italic. (src/engine/font-manager.js:132-140) — **UMLCraft:** ✅ present a user font (not `predefined`) draws the face it names on the canvas, in the inline editor, in PNG pictures (loaded into the renderer's font list) and in the PDF; SVG pictures name the face first in `font-family` (src/fonts.rs:120-151, 276-306; src/render.rs:1373-1383, 1498-1501; src/pdf_font.rs:125-148, 149-178)
- **Custom keymap file** — `<userData>/keymap.json`, if present, is merged over the default keymaps after the extensions load. (src/app-context.js:495-506, 644) — **UMLCraft:** ✅ present `keymap.json` in UMLCraft's settings folder is read at start-up; its bindings replace the built-in ones for their keystrokes, run before the built-in shortcuts and show in the menus (src/keymap.rs:156-212; src/main.rs:254)
- **Theme applied at start-up** — the preference `theme.default` (default `"dark"`) sets the theme CSS. Changing the preference re-themes the window live. (src/app-context.js:629-630, 1520-1522) — **UMLCraft:** ✅ present `theme.default` (default "dark") picks the dark theme, with colours measured from StarUML's dark CSS, or UMLCraft's own light theme, at start-up and live (src/main.rs:116-137; src/ui.rs:29-66, 3076-3083)
- **Preference changes repaint** — any preference change repaints the diagram. A change to `diagramEditor.showGrid` also syncs the View › Show Grid check state. (src/app-context.js:1518-1528) — **UMLCraft:** ✅ present the canvas is redrawn every frame, so a preference takes effect at once, and Show Grid and Snap to Grid in Preferences are the same settings as the View menu's check items (src/prefs.rs:419-421; src/ui.rs:1964)
- **Native context menus by selector** — the renderer registers context menu templates per CSS selector. The main process builds native menus and pops them up. Enabled, visible and checked states are mirrored into both the app menu and the context menus. (src/main-process/context-menu.js:115-148, src/main-process/application.js:281-306) — **UMLCraft:** ✅ present egui context menus on the canvas, Explorer rows and Working Diagrams, built in code, their enabled and checked states computed as they are drawn, as the main menus' are (src/ui.rs:844, 1897; src/canvas.rs:893, 2708). - **Browser default context menu suppressed** — `document.oncontextmenu` returns false. (src/app-context.js:620-622) — **UMLCraft:** ➖ n/a there is no browser context menu to suppress
- **Text-field edit commands delegate to the browser** — Undo, Redo, Cut, Copy and Paste act on the focused `<input>`/`<textarea>` (through webContents) instead of the model. Select All selects the text in a focused field, and otherwise all views in the diagram. (src/engine/default-commands.js:591-616, 859-868) — **UMLCraft:** ✅ present while a text field has focus the edit keys (undo, redo, cut, copy, paste, select all, Delete, Backspace) are left to egui's field; otherwise Ctrl+A selects every view in the diagram (src/keymap.rs:142-147; src/ui.rs:2790-2900; src/canvas.rs:2297-2302)
- **Splash screen** — a splash screen shows until app-ready. (src/app-context.js:737) — **UMLCraft:** ✅ present the window first shows the app icon, name and version on the panel colour, then opens its start-up file on the next frame (src/window.rs:322-330, 354-376)

## Auto-backup and crash recovery

- **Auto-backup every 10 minutes** — while `general.auto-backup` is on, the whole project is serialized to `<userData>/__backup.mdj` every 10 minutes, and its path is recorded in localStorage `__backup_filename`. (src/app-context.js:91, 1533-1553) — **UMLCraft:** ✅ present while general.auto-backup is on, the project is written to `__backup.mdj` next to the preferences file every 10 minutes, and its path is recorded as `__backup_filename` (src/prefs.rs:499-516)
- **Clean exit clears backup marker** — `window.onbeforeunload` removes `__backup_filename`, so the backup is offered only after an abnormal exit. (src/app-context.js:809-811) — **UMLCraft:** ✅ present closing the window normally removes the marker and the backup (src/prefs.rs:518-525; src/ui.rs:2973)
- **Crash recovery on launch** — if the marker exists and the file is present, a red toast "App was unexpectedly terminated. Auto backup file has loaded." appears. The backup is loaded as an untitled project (no filename), marked modified, and the backup file is deleted. New, New-from-template and Open windows skip this (`skipLoadBackup`). (src/app-context.js:697-708, src/main-process/application.js:246-258) — **UMLCraft:** ✅ present when the marker is there at a launch not made by another window, the backup is loaded as an untitled, modified project and deleted, with the red toast "App was unexpectedly terminated. Auto backup file has loaded." (src/prefs.rs:688-699; src/window.rs:180-184)

(src/engine/project-manager.js:182-197, src/main-process/application.js:249-253) — **UMLCraft:** ✅ present File › New From Template opens a built-in template as a new project with no file name and no changes, so the next Save asks for one (src/ui.rs:1713-1723; src/app.rs:379-384). (src/engine/default-commands.js:148-175, src/engine/project-manager.js:126-145) — **UMLCraft:** ✅ present tab-indented JSON to the current file, or the "Save Project As" dialog when untitled, starting at "Untitled.mdj" with the "Models" filter first, then "All Files"; `.mdj` is added to a name without an extension; modified flag cleared. - **Save As** — `project:save-as` always opens the Save dialog. (src/engine/default-commands.js:148-171) — **UMLCraft:** ✅ present Save As always opens the Save dialog (Ctrl+Shift+S) (src/app.rs:490-504, src/ui.rs:1744, src/ui.rs:2341)
- **Open** — an "Open" dialog with the Models filter opens. A failed load shows "Failed to open <path>". Loading closes the current project, clears undo and redo, expands the project root in the Explorer, and repaints after 100 ms. (src/engine/default-commands.js:183-234, src/engine/project-manager.js:152-175, src/app-context.js:972-1010) — **UMLCraft:** ✅ present the "Select a model file..." dialog with Models and All Files filters; in a new window when this one has a file or changes; a failure shows "Failed to open the file." with the error; loading clears undo/redo and selection and expands the root and its children (src/window.rs:250-264; src/app.rs:458-470)
- **Close project / window** — `project:close` closes the window, with the unsaved-changes prompt. (src/engine/default-commands.js:345-347, src/app-context.js:1031-1043) — **UMLCraft:** ✅ present File › Close (and `project:close`) closes the window, with the unsaved-changes prompt (src/ui.rs:2411-2415; src/palette.rs:350; src/window.rs:270-292)

(src/engine/default-commands.js:678-700) — **UMLCraft:** ✅ present the current diagram goes to the system clipboard as a picture, with a white background outside macOS (the original uses JPEG there) (src/clipboard.rs:162-195)

The defaults are all, landscape, A4 and show name. (src/dialogs/print-dialog.js:16-60) — **UMLCraft:** ✅ present range, layout, page size and show name, kept in the `print.options` preference (src/pdf.rs:528-552, 554-617)

- **PDF save** — a Save dialog opens with default `filenamify(project.name).pdf`, and `.pdf` is appended if missing. "All" collects every Diagram by project traversal order. "No current diagram." appears if the list is empty. (src/engine/default-commands.js:541-585) — **UMLCraft:** ✅ present Save asks for the file, `filenamify(project name).pdf` by default, and adds `.pdf` when missing; "All" walks the project in order; an empty list shows "No current diagram." (src/pdf.rs:453-488, 605-614)
- **One diagram per page, fit-to-page** — the page margin is 30pt. The scale is `min(pageW/box.x2, pageH/box.y2)`, capped at 1, so diagrams are never enlarged. The diagram name (its pathname) is drawn in Helvetica 10 above the diagram when "show name" is on. (src/engine/diagram-export.js:318-362) — **UMLCraft:** ✅ present 30 pt margin, scale `min(pageW/x2, pageH/y2)` capped at 1, path name in 10 pt above the diagram (src/pdf.rs:484-523). ## UML text grammars (inline edit, PEG.js) and how they are applied

- **Name expression** `<<stereotype>> [+|#|-|~]name`: sets the name and the visibility (+ public, # protected, - private, ~ package). The stereotype is looked up by name as a UMLStereotype from the element's scope. If it is found, a reference is set. If not, the stereotype is stored as a plain string. Omitting the stereotype clears it. (uml/grammars/uml-name.pegjs; uml-commands.js:288) — **UMLCraft:** ✅ present `<<stereotype>>` (or `«stereotype»`) and the visibility sign are parsed; a UMLStereotype of that name anywhere in the project is linked, otherwise the text is stored; no stereotype clears it (src/parse.rs:19-115; src/canvas.rs:1803-1807)
- **Attribute expression** `<<st>> vis name : type [mult] = default`: the type is resolved to a UMLClassifier by name, or kept as a string if not found. Multiplicity takes only digits, `.` and `*`. Any part left out is reset: type becomes null, multiplicity and default become "". (uml/grammars/uml-attribute.pegjs; uml-commands.js:331) — **UMLCraft:** ✅ present stereotype, visibility sign, `/` derived, name, `: type`, `[mult]` and `= default` are parsed and left-out parts reset (type removed, multiplicity/default ""); the type is linked to a classifier of that name, else kept as a string. Multiplicity characters are not restricted (src/parse.rs:136-170)
- **Operation expression** `<<st>> vis name(in|out|inout p : T [m] = d, ...) : ReturnType [m]`: the whole edit runs as one undoable "change operation". Existing parameters are updated in place by position, extra ones are created and surplus ones are deleted. A parameter with no direction defaults to `in`. A return parameter is created, updated or removed to match the return type. Leaving out the parentheses removes all parameters. (uml/grammars/uml-operation.pegjs; uml-commands.js:398) — **UMLCraft:** ✅ present one undo step; stereotype, visibility, name, `in`/`out`/`inout` (default `in`), `: T [m] = d` per parameter, updated in place by position with extras created and surplus deleted; the return parameter follows the return type; no parentheses removes every parameter.
