# Panels, views and dialogs

Part of the [StarUML feature inventory](README.md); the legend and how to update a status are there.

Taken from the extracted source under `staruml/app/src`. Paths are relative to `app/src`. Each bullet is something seen in the code. When a behaviour comes from a widget library (Kendo) and not from StarUML code, the bullet says so.

## Global window and layout

- **Main layout** — There are four areas. The left sidebar holds Working Diagrams with the Toolbox below it. The centre holds the diagram canvas, bottom panels sit under it, and a thin toolbar strip runs down the right edge. The right navigator holds Model Explorer with the Editors below it. The statusbar runs along the bottom. (static/html-contents/main-view.html:12-66) — **UMLCraft:** ✅ present Same four areas: sidebar (Working Diagrams over a Toolbox bottom panel), navigator (Model Explorer over Editors), toolbar strip between canvas and navigator, statusbar at the bottom; there is no bottom-panel area under the canvas (src/ui.rs:1487-1505)
- **Links open in the system browser** — Clicking any `<a href>` anywhere in the app, except `#` anchors, opens the URL with the OS browser and never navigates the window. A capture-phase handler does this, so it also covers middle-clicks. (app-context.js:524-541) — **UMLCraft:** ➖ n/a The UI has no hyperlinks (the About dialog has no link), so there is nothing to route to a browser
- **Drop a .mdj file on the window** — Dropping files on the app runs `project:open` for each file whose extension is the app extension (.mdj). Any other file dropped outside the canvas is ignored and does not replace the page. (app-context.js:546-565) — **UMLCraft:** ❌ missing Files dropped on the window are ignored: nothing reads egui's dropped files. A model opens only through File > Open or the command line (src/main.rs:146, src/ui.rs:1244-1251)
- **Built-in browser context menu disabled** — `document.oncontextmenu` returns false. Only the app's own context menus appear. (app-context.js:620) — **UMLCraft:** ➖ n/a Native egui window with no browser context menu. Only the app's own menus exist (src/canvas.rs:535, src/ui.rs:242)
- **Diagram area refits to layout changes** — Toggling or resizing the sidebar, navigator, toolbar, statusbar or a bottom panel calls `diagramEditor.fitSize()`. (app-context.js:814-830; ui/panel-manager.js:91-139) — **UMLCraft:** ✅ present The canvas is the egui CentralPanel, which takes whatever space the panels leave, every frame, and the canvas rect is re-read each frame (src/ui.rs:1503-1505, src/canvas.rs:260-261)
- **Theme switch is live** — Changing the `theme.default` preference swaps the theme CSS straight away. Any preference change also repaints the diagrams. (app-context.js:1518-1527) — **UMLCraft:** ❌ missing No theme preference: the dark visuals are fixed at start-up (src/main.rs:89-109)
- **Startup selection** — At launch the project root is selected in Model Explorer, and the statusbar zoom is set from the editor's zoom. (app-context.js:680-682) — **UMLCraft:** 🟡 partial The status bar shows the current zoom from the start, but no element is selected at launch: set_project sets focus to None, so the project root is expanded but not selected (src/app.rs:235-246, src/ui.rs:793)
- **Crash-recovery toast** — If an auto-backup file exists at launch, it is loaded as a modified untitled project and an error toast reads "App was unexpectedly terminated. Auto backup file has loaded." (app-context.js:698-708) — **UMLCraft:** ❌ missing No auto-backup and no crash recovery. A file opens only if it is passed on the command line (src/main.rs:175-177)

## Panel resizing and hiding (Resizer / PanelManager)

- **Drag a splitter to resize** — Each resizable panel has a splitter bar on one edge. Dragging it resizes the panel live, one update per animation frame. The sidebar's splitter is on its right edge, the navigator's on its left, and the Toolbox and Editors have theirs on top. (utils/resizer.js:141-147,269-359; static/html-contents/main-view.html:12,18,54,60) — **UMLCraft:** ❌ missing Every panel has a fixed size (exact_size) and no splitter (src/ui.rs:1491-1498)
- **Drag below 10 px to collapse** — Dragging a panel below 10 px hides it. Dragging the splitter of a hidden panel back out past 10 px shows it again at the dragged size. (utils/resizer.js:303-323) — **UMLCraft:** ❌ missing No splitters, so there is no drag-to-collapse. Panels hide only through the View menu checkboxes (src/ui.rs:960-962)
- **Minimum sizes** — The sidebar and navigator have a minimum of 0. The Toolbox and Editors have a minimum height of 60 px. A panel can never be dragged larger than its parent. (static/html-contents/main-view.html:12,18,54,60; utils/resizer.js:335-353) — **UMLCraft:** ❌ missing Sizes are fixed constants (sidebar 200, navigator 300, toolbox and editors 400). There are no minimum or maximum limits because nothing can be resized (src/ui.rs:15-20)
- **Collapsed panel keeps a grab handle** — When a collapsible panel is hidden, its splitter stays docked at the window edge, so it can be dragged open again. (utils/resizer.js:238-258) — **UMLCraft:** ❌ missing No splitters, so a hidden panel leaves no grab handle (src/ui.rs:1490-1501)
- **Size and visibility persisted** — When a drag ends, the panel's size, content size and visibility are saved to the `_viewState.<panelId>` preference. They are restored at the next launch. (utils/resizer.js:373-386,407-424; core/preference-manager.js:186-205) — **UMLCraft:** ❌ missing Nothing is persisted: panel visibility resets to shown at each launch (src/app.rs:196-198)
- **Double-click splitter toggle (disabled)** — The code for double-click-to-collapse exists, but the shield that catches the second click is removed after 0 ms, so in practice it does nothing ("DISABLED DOUBLE CLICK… ISSUE #255"). (utils/resizer.js:361-398) — **UMLCraft:** ➖ upstream bug Dead double-click code in the original. UMLCraft has no splitters and does not copy it
- **Nested split keeps 40 px for the upper view** — Inside the navigator, the Editors pane is shrunk so that Model Explorer keeps at least 40 px. Inside the sidebar, the Toolbox is shrunk so that Working Diagrams keeps at least 40 px. Both limits are applied again when the window is resized. (views/navigator-view.js:18,65-71,151-157; views/sidebar-view.js:18,69-75,150-156) — **UMLCraft:** ❌ missing The Toolbox and Editors are fixed at 400 px high, so in a short window they can squeeze Working Diagrams and Model Explorer below 40 px (src/ui.rs:19-20,1492,1498)
- **Scroll shadows hidden while resizing** — Scroller shadows are hidden while a drag is in progress and recomputed when it ends. (views/sidebar-view.js:92-103; views/navigator-view.js:92-105) — **UMLCraft:** ❌ missing No scroll shadows and no resizing (src/ui.rs:340,699)
- **Bottom panels** — Extensions and the validation panel can add panels below the diagram area. Each one has a top splitter and starts hidden. Its maximum height is capped to the diagram area height plus its own height, and the caps are recomputed when panels change or the window is resized. (ui/panel-manager.js:56-82,103-128,149-209) — **UMLCraft:** ❌ missing No bottom panels: there is no extension or validation panel under the canvas (src/ui.rs:1484-1505)
- **Toggle Sidebar** — `view:sidebar` (Ctrl+1) shows or hides the left sidebar. The View menu check mark follows its state. (views/sidebar-view.js:38-40,77-82,106-117,158) — **UMLCraft:** 🟡 partial View > Sidebar checkbox shows or hides it and the check mark follows, but there is no Ctrl+1 shortcut (src/ui.rs:960,1490; src/ui.rs:1082-1236)
- **Toggle Navigator** — `view:navigator` (Ctrl+2) shows or hides the right navigator. The menu check mark follows. (views/navigator-view.js:38-40,73-78,107-118,159) — **UMLCraft:** 🟡 partial View > Navigator checkbox works and the check mark follows, but there is no Ctrl+2 shortcut (src/ui.rs:961,1496)
- **Toggle Toolbar** — `view:toolbar` (Ctrl+3) shows or hides the right toolbar strip, and the content area's right offset is adjusted. Visibility is saved in view state `toolbar`. (views/toolbar-view.js:32-70,93-104) — **UMLCraft:** ❌ missing The toolbar strip is always shown, with no toggle and no shortcut (src/ui.rs:1502)
- **Toggle Statusbar** — `view:statusbar` (Ctrl+4) shows or hides the statusbar, and the main view's bottom offset is adjusted. Visibility is saved in view state `statusbar` and restored at startup. (views/statusbar-view.js:122-160,190-201) — **UMLCraft:** 🟡 partial View > Statusbar checkbox works, but there is no Ctrl+4 shortcut and the state is not saved or restored (src/ui.rs:962,1487; src/app.rs:198)

(views/editors-holder-view.js:32-34,92-97,111-124) — **UMLCraft:** ❌ missing The Editors pane cannot be hidden on its own: there is no menu item and no Ctrl+6 (src/ui.rs:1497-1500)
