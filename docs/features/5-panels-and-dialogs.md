# Panels, views and dialogs

Part of the [StarUML feature inventory](README.md); the legend and how to update a status are there.

Taken from the extracted source under `staruml/app/src`. Paths are relative to `app/src`. Each bullet is something seen in the code. When a behaviour comes from a widget library (Kendo) and not from StarUML code, the bullet says so.

## Global window and layout

- **Main layout** — There are four areas. The left sidebar holds Working Diagrams with the Toolbox below it. The centre holds the diagram canvas, bottom panels sit under it, and a thin toolbar strip runs down the right edge. The right navigator holds Model Explorer with the Editors below it. The statusbar runs along the bottom. (static/html-contents/main-view.html:12-66) — **UMLCraft:** ✅ present Same four areas: sidebar (Working Diagrams over a Toolbox bottom panel), navigator (Model Explorer over Editors), toolbar strip between canvas and navigator, statusbar at the bottom; there is no bottom-panel area under the canvas (src/ui.rs:2548-2566)
- **Links open in the system browser** — Clicking any `<a href>` anywhere in the app, except `#` anchors, opens the URL with the OS browser and never navigates the window. A capture-phase handler does this, so it also covers middle-clicks. (app-context.js:524-541) — **UMLCraft:** ➖ n/a The UI has no hyperlinks (the About dialog has no link), so there is nothing to route to a browser
- **Drop a .mdj file on the window** — Dropping files on the app runs `project:open` for each file whose extension is the app extension (.mdj). Any other file dropped outside the canvas is ignored and does not replace the page. (app-context.js:546-565) — **UMLCraft:** ✅ present A .mdj file dropped on the window opens after the unsaved-changes prompt; other files are ignored (src/ui.rs:2112-2121)
- **Built-in browser context menu disabled** — `document.oncontextmenu` returns false. Only the app's own context menus appear. (app-context.js:620) — **UMLCraft:** ➖ n/a Native egui window with no browser context menu. Only the app's own menus exist (src/canvas.rs:601, src/ui.rs:344)
- **Diagram area refits to layout changes** — Toggling or resizing the sidebar, navigator, toolbar, statusbar or a bottom panel calls `diagramEditor.fitSize()`. (app-context.js:814-830; ui/panel-manager.js:91-139) — **UMLCraft:** ✅ present The canvas is the egui CentralPanel, which takes whatever space the panels leave, every frame, and the canvas rect is re-read each frame (src/ui.rs:2688-2690, src/canvas.rs:288-289)
- **Theme switch is live** — Changing the `theme.default` preference swaps the theme CSS straight away. Any preference change also repaints the diagrams. (app-context.js:1518-1527) — **UMLCraft:** ✅ present Changing `theme.default` in Preferences re-styles the window on the next frame; the diagrams repaint every frame anyway (src/ui.rs:2583-2590; src/main.rs:114-135)
- **Startup selection** — At launch the project root is selected in Model Explorer, and the statusbar zoom is set from the editor's zoom. (app-context.js:680-682) — **UMLCraft:** ✅ present the project is selected in the explorer when a project starts, opens or is created, and the status bar shows the zoom from the start (src/app.rs:354-355)
- **Crash-recovery toast** — If an auto-backup file exists at launch, it is loaded as a modified untitled project and an error toast reads "App was unexpectedly terminated. Auto backup file has loaded." (app-context.js:698-708) — **UMLCraft:** ✅ present After an abnormal exit the auto-backup is loaded at the next launch without a file, as a modified untitled project, with the toast "App was unexpectedly terminated. Auto backup file has loaded." (src/prefs.rs:503; src/main.rs:243)

## Panel resizing and hiding (Resizer / PanelManager)

- **Drag a splitter to resize** — Each resizable panel has a splitter bar on one edge. Dragging it resizes the panel live, one update per animation frame. The sidebar's splitter is on its right edge, the navigator's on its left, and the Toolbox and Editors have theirs on top. (utils/resizer.js:141-147,269-359; static/html-contents/main-view.html:12,18,54,60) — **UMLCraft:** ✅ present the sidebar (right edge), navigator (left edge), Toolbox and Editors (top edge) and the panels under the diagram (top edge) resize live while their edge is dragged, with a resize cursor over it (src/splitter.rs:60-104; src/ui.rs:2628-2722)
- **Drag below 10 px to collapse** — Dragging a panel below 10 px hides it. Dragging the splitter of a hidden panel back out past 10 px shows it again at the dragged size. (utils/resizer.js:303-323) — **UMLCraft:** ✅ present dragging the sidebar, the navigator or a panel under the diagram below 10 px hides it; dragging a hidden sidebar or navigator's handle past 10 px shows it at the dragged size. The Toolbox and Editors stop at 60 px instead (src/splitter.rs:47-55; src/ui.rs:2691-2722)
- **Minimum sizes** — The sidebar and navigator have a minimum of 0. The Toolbox and Editors have a minimum height of 60 px. A panel can never be dragged larger than its parent. (static/html-contents/main-view.html:12,18,54,60; utils/resizer.js:335-353) — **UMLCraft:** ✅ present the sidebar and navigator go down to 0 (then hide) and never get wider than the window minus the other side panels; the Toolbox and Editors stop at 60 px (src/splitter.rs:13-17; src/ui.rs:2634-2664, 2691-2706)
- **Collapsed panel keeps a grab handle** — When a collapsible panel is hidden, its splitter stays docked at the window edge, so it can be dragged open again. (utils/resizer.js:238-258) — **UMLCraft:** ✅ present a hidden sidebar or navigator leaves a 4 px handle at the window edge that can be dragged open; panels under the diagram, opened from the menus, leave none (src/ui.rs:2698-2709)
- **Size and visibility persisted** — When a drag ends, the panel's size, content size and visibility are saved to the `_viewState.<panelId>` preference. They are restored at the next launch. (utils/resizer.js:373-386,407-424; core/preference-manager.js:186-205) — **UMLCraft:** ✅ present panel visibility (Sidebar, Navigator, Statusbar, Toolbox, Editors, the panels under the diagram), the folded editor sections and the dragged panel sizes (`_viewState.<panel>.size`) are kept in the preferences file and restored at launch (src/prefs.rs:77-130)
- **Double-click splitter toggle (disabled)** — The code for double-click-to-collapse exists, but the shield that catches the second click is removed after 0 ms, so in practice it does nothing ("DISABLED DOUBLE CLICK… ISSUE #255"). (utils/resizer.js:361-398) — **UMLCraft:** ➖ upstream bug Dead double-click code in the original. UMLCraft has no splitters and does not copy it
- **Nested split keeps 40 px for the upper view** — Inside the navigator, the Editors pane is shrunk so that Model Explorer keeps at least 40 px. Inside the sidebar, the Toolbox is shrunk so that Working Diagrams keeps at least 40 px. Both limits are applied again when the window is resized. (views/navigator-view.js:18,65-71,151-157; views/sidebar-view.js:18,69-75,150-156) — **UMLCraft:** ✅ present the Toolbox and Editors are drawn no taller than their side panel minus 40 px, so Working Diagrams and Model Explorer keep 40 px, also after the window shrinks (src/ui.rs:2634-2664)
