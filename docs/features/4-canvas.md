# Diagram canvas and editing

Part of the [StarUML feature inventory](README.md); the legend and how to update a status are there.

Source: the extracted `app/` tree. Paths below are relative to `app/`. Each bullet is a behaviour found in the code. Where something looks like a bug or quirk, it says so, because a parity port has to decide whether to copy it.

## Mouse buttons and modifiers (canvas-level dispatch)

- **Left button goes to the active tool**: a left press, move or release without Ctrl/Cmd goes to the active handler (the Select tool or a create tool). (src/ui/diagram-editor.js:2190) — **UMLCraft:** ✅ present a left press with no tool goes to selection, with a tool to node/edge creation (src/canvas.rs:367, 484)
- **Ctrl/Cmd + left-drag pans**: holding Ctrl (or Cmd/Meta) while left-dragging moves the viewport. The cursor becomes `move`, and the delta is divided by the zoom scale so the content follows the pointer. (src/ui/diagram-editor.js:2178, 2236-2244) — **UMLCraft:** ❌ missing Ctrl+left-drag does not pan; Ctrl acts like Shift and toggles selection or adds to the rubber band (src/canvas.rs:514)
- **Ctrl/Cmd blocks all editing**: while Ctrl or Meta is held, press, move and release never reach the tool. Ctrl+click does not select, and Ctrl+drag never moves views. (src/ui/diagram-editor.js:2178-2193, 2208-2220) — **UMLCraft:** ❌ missing Ctrl is an add-to-selection modifier, and Ctrl+drag on a view moves it (src/canvas.rs:514-536)
- **Middle-button drag pans**: pressing the middle button and dragging pans the same way as Ctrl+drag. The cursor resets on release. (src/ui/diagram-editor.js:2185-2189, 2245-2251, 2213-2217) — **UMLCraft:** ✅ present middle-button drag pans, delta divided by zoom, clamped at 0. No cursor change (src/canvas.rs:375-378, 593-596)
- **Right-click on empty canvas**: deselects everything (it also runs a zero-size area selection at the point). (src/ui/diagram-editor.js:701-704) — **UMLCraft:** 🟡 partial a right-click on empty canvas opens the menu with ctx_target = None but leaves the selection as it was (src/canvas.rs:416-427)
- **Right-click on an unselected view**: selects only that view, so the context menu targets it. (src/ui/diagram-editor.js:705-707) — **UMLCraft:** ✅ present selects only that view before the context menu (src/canvas.rs:421-424)
- **Right-click on a selected view**: keeps the whole current selection, so the context menu applies to the multi-selection. (src/ui/diagram-editor.js:705-708) — **UMLCraft:** ✅ present the selection is kept if the view is already in it (src/canvas.rs:422)
- **Alt is ignored**: Alt is captured in the event object but no handler reads it. (src/ui/diagram-editor.js:86-96) — **UMLCraft:** ✅ present no canvas handler reads Alt (src/canvas.rs:336, 514)
- **Every mouse-up emits a canvas "mouseDown" event**: the editor emits its `mouseDown` event on mouse-up, and the app closes any open quick edit in response. Any click on the canvas therefore dismisses the popup. (src/ui/diagram-editor.js:2221; src/app-context.js:1318-1324) — **UMLCraft:** ✅ present every primary press on the canvas commits and closes the inline editor first. It happens on press, not release (src/canvas.rs:367-373)
- **Selection change focuses the canvas**: whenever the canvas selection changes, the `<canvas>` element gets keyboard focus, so canvas keys work straight away. (src/ui/diagram-manager.js:657-660) — **UMLCraft:** 🟡 partial the canvas takes focus only when it is pressed. A selection made from the explorer leaves focus there (src/canvas.rs:369; src/ui.rs:213)

## Wheel, zoom and scrolling

- **Wheel scrolls**: a plain wheel event moves the origin by (−deltaX, −deltaY) in raw pixels, not divided by zoom. Two-axis trackpads pan freely. (src/ui/diagram-editor.js:2284-2287) — **UMLCraft:** 🟡 partial wheel scrolls on both axes, but the delta is divided by zoom (diagram units, not raw pixels) (src/canvas.rs:360-364)
- **Shift+wheel scrolls horizontally**: with Shift held and no horizontal delta, the vertical delta is applied to X. The code comment says this is for non-macOS. (src/ui/diagram-editor.js:2281-2283) — **UMLCraft:** ✅ present with Shift the vertical delta goes to X (src/canvas.rs:361)
- **Ctrl/Cmd+wheel zooms**: each wheel event changes the zoom by ±0.1. Wheel down zooms out and wheel up zooms in. The default browser zoom is prevented. The zoom anchor is the origin, not the cursor or the screen centre. (src/ui/diagram-editor.js:2273-2280) — **UMLCraft:** ✅ present Ctrl/Cmd+wheel steps zoom by ±0.1. The scroll origin (top-left) stays fixed, the same anchor as the original (src/canvas.rs:357-359; src/app.rs:659-661)
- **Zoom limits**: the zoom scale is clamped to 0.1–3.0. (src/ui/diagram-editor.js:2396-2406) — **UMLCraft:** ✅ present clamped to 0.1–3.0 (src/app.rs:10-11, 660)
- **Zoom In/Out commands keep the screen centre**: View > Zoom In/Out changes the zoom by ±0.1 and then re-centres on the point that was at the screen centre. (src/engine/default-commands.js:1063-1077) — **UMLCraft:** 🟡 partial ±0.1 steps exist (menu, toolbar, Ctrl+=/-), but there is no re-centring: the top-left stays fixed (src/ui.rs:876-881, 957-962)
- **Actual Size**: sets the zoom to 1.0 and keeps the current screen centre. (src/engine/default-commands.js:1079-1084) — **UMLCraft:** 🟡 partial sets zoom to 1.0 without keeping the screen centre (src/ui.rs:882-884, 963-965)
- **Fit to Window**: zoom = min(viewport width / diagram bounding-box width, viewport height / diagram bounding-box height), capped at 1.0 so it never zooms in. It then centres on the diagram's bounding box. (src/engine/default-commands.js:1086-1101) — **UMLCraft:** 🟡 partial zoom = min(w/(right+20), h/(bottom+20)), floored to 0.1 and capped at 1.0. It measures from (0,0), not the bounding box, and scrolls to (0,0) instead of centring (src/canvas.rs:998-1008)
- **Zoom shown in the status bar**: every zoom change updates the status-bar zoom readout. (src/app-context.js:1467-1473) — **UMLCraft:** ✅ present the status bar shows the zoom % every frame (src/ui.rs:734)
- **No scrolling into negative space**: the origin is clamped to ≤ 0 on both axes, so you cannot pan left of or above diagram coordinate (0,0). (src/ui/diagram-editor.js:2380-2383) — **UMLCraft:** ✅ present scroll is clamped at ≥ 0 for wheel, pan and minimap (src/canvas.rs:362-363, 191, 594-595)
- **Scroll position remembered per diagram**: the origin is saved on the diagram (`_originX` and `_originY`) at every scroll, and restored when you switch back to that diagram. A diagram that has never been scrolled starts at (0,0). (src/ui/diagram-editor.js:2384-2387; src/ui/diagram-manager.js:218-228, 243) — **UMLCraft:** ❌ missing there is only one App.scroll. Switching diagrams resets it to (0,0), and nothing is stored on the diagram (src/app.rs:596-600)
- **Scroll-to-view centring**: "select in diagram" centres the viewport on the view's bounding-box centre, taking zoom into account and clamping at 0. (src/ui/diagram-manager.js:340-348, 484-490) — **UMLCraft:** ❌ missing selecting from the explorer or by --element never scrolls the canvas to the view (src/app.rs:624-630, 664-676)
- **Canvas fills the diagram area, HiDPI aware**: the canvas is resized to `#diagram-area` whenever the window resizes, with a backing store scaled by `devicePixelRatio`. It is a viewport, not a fixed-size page. (src/ui/diagram-editor.js:2295-2297, 2318-2333) — **UMLCraft:** ✅ present the canvas is the central panel's max_rect, and egui handles pixels-per-point/HiDPI (src/canvas.rs:195-198)

## Grid and snapping

- **Grid defaults**: the default grid size is 8 px, and both show-grid and snap are on. The real values come from the preferences `diagramEditor.gridSize`, `diagramEditor.showGrid` and `diagramEditor.snapToGrid`, read at start-up. (src/ui/diagram-editor.js:2146-2152; src/ui/diagram-manager.js:837-849) — **UMLCraft:** 🟡 partial hard-coded: grid 8, show-grid and snap on. There are no preferences (src/render.rs:10; src/app.rs:145-146)
- **Grid lines every two cells**: the visible grid is drawn every `gridSize*2` units, in diagram coordinates so it zooms with the content, with a hairline width of 1/devicePixelRatio. The background and grid colours come from the preferences `diagramEditor.backgroundColor` and `diagramEditor.gridColor`. (src/ui/diagram-editor.js:2499-2538) — **UMLCraft:** 🟡 partial lines every 16 units (2×grid) in diagram coordinates, 1 px. The grid colour is a fixed constant and the background is fixed white, with no preferences (src/render.rs:11-13; src/canvas.rs:218-236)
- **Snap off means a 1-px grid**: turning snap off sets the grid factor to 1×1, so every grid-fitting operation becomes a no-op. Turning it on restores `gridSize`. (src/ui/diagram-editor.js:2304-2316) — **UMLCraft:** ✅ present with snap off, coordinates only round to whole pixels (src/canvas.rs:162-164)
- **Changing grid size takes effect live**: changing the `diagramEditor.gridSize` preference immediately updates the snap factor and repaints. (src/ui/diagram-manager.js:827-831) — **UMLCraft:** ❌ missing no grid-size preference; GRID_SIZE is a constant (src/render.rs:10)
- **Show Grid / Snap to Grid persist**: both toggles write to preferences, so they survive restarts, and they update the menu check marks. (src/ui/diagram-manager.js:426-462; src/engine/default-commands.js:1103-1115) — **UMLCraft:** 🟡 partial View menu checkboxes and Ctrl+G / Ctrl+Shift+G toggle them, but they are not persisted across restarts (src/ui.rs:890-891, 969-974)
- **Small drags do not jump to the grid**: when moving or resizing, a coordinate that stays between its original value and the next grid line keeps the original (unsnapped) value. Only once it crosses into another grid cell does it snap to a grid multiple. An off-grid element therefore stays put on tiny drags. (src/ui/diagram-editor.js:1201-1323, 1892-1915) — **UMLCraft:** ❌ missing snap_v always rounds to the nearest grid multiple, so an off-grid node jumps on its first snapped move (src/canvas.rs:162-164, 643-647)

## Hit-testing and hover feedback

- **Topmost view wins**: hit-testing sorts the diagram's top-level views by `selectZIndex` and tests from the top down. Inside a view it recurses into subviews from last to first and returns the deepest selectable view under the point. (src/core/core.js:4049-4080, 1794-1807) — **UMLCraft:** 🟡 partial top-level ownedViews are tested from last to first, but there is no recursion into subviews; the top-level view is always returned (src/canvas.rs:132-148)
- **Non-selectable parts pass clicks to the parent**: views with `selectable = SK_NO` are skipped, which is the default for plain LabelView. Clicking a label therefore picks its owner. (src/core/core.js:3435-3440, 1794-1806) — **UMLCraft:** 🟡 partial node labels pick their owner because only top-level views are tested. Edge labels cannot be hit at all, since only line segments are tested (src/canvas.rs:127-130, 132-148)
- **The selected view keeps priority**: if exactly one view is selected and you press inside its selection-handle zone (outside its bounding box but still "containing" the point), or anywhere on a selected edge, that view is the target even if another view lies underneath. Overlapping views do not steal handle grabs. (src/ui/diagram-editor.js:556-585, 629-636) — **UMLCraft:** ✅ present for a single selected node, handles are tested before hit_view. For a single selected edge, its points and segments are tested first (src/canvas.rs:492-513)
- **Resize handle size**: handles are 8×8 screen pixels (half-size 4), centred 4 px outside each corner and edge midpoint of the node's zoomed bounding box. (src/core/graphics.js:2726-2727; src/ui/diagram-editor.js:204-299) — **UMLCraft:** 🟡 partial handles are drawn 8×8 but centred on the corners and edge midpoints, not 4 px outside. The hit zone is ±6 screen px (src/render.rs:16, 336-342; src/canvas.rs:158-159, 246-251)
- **Hover cursor on node handles**: with exactly one node selected, hovering a handle shows nwse-resize (top-left and bottom-right), nesw-resize (top-right and bottom-left), ns-resize (top and bottom middle) or ew-resize (left and right middle). Elsewhere the cursor is the default. (src/ui/diagram-editor.js:183-327) — **UMLCraft:** ✅ present nwse/nesw/ns/ew resize cursors on the 8 handles when exactly one node is selected (src/canvas.rs:389-404)
- **Hover cursors respect sizability**: free-sizable and ratio nodes show corner and middle handles. Horizontal-only nodes show only the left and right handles, vertical-only nodes only top and bottom. Non-sizable or auto-resize nodes show no resize cursors. (src/ui/diagram-editor.js:195-300) — **UMLCraft:** ❌ missing every node shows all 8 handles and resize cursors; there is no sizable or autoResize check (src/canvas.rs:150-160)
- **Hover cursor on edge endpoints**: with exactly one edge selected, hovering its first or last point shows the `pointer` (hand) cursor, meaning it can be reconnected. (src/ui/diagram-editor.js:396-401) — **UMLCraft:** ❌ missing edge endpoints are not handles and get no pointer cursor (src/canvas.rs:150-157)
- **Hover cursor on bend points**: hovering an intermediate point of an edge with more than 2 points shows the `move` cursor. (src/ui/diagram-editor.js:377-403) — **UMLCraft:** ❌ missing no move cursor on bend points (src/canvas.rs:389-404)
- **Hover cursor on segments**: within 4 px of a segment, a rectilinear or rounded-rectilinear edge shows ns-resize on horizontal segments and ew-resize on vertical ones. Oblique and curve edges show `crosshair`. (src/ui/diagram-editor.js:344-411) — **UMLCraft:** ❌ missing no segment cursors (src/canvas.rs:389-404)
- **No hover feedback with multiple or zero selections**: the hover cursor logic runs only when exactly one view is selected. (src/ui/diagram-editor.js:169-172) — **UMLCraft:** ✅ present handle cursors only appear when selection.len()==1 (src/canvas.rs:151)
- **No hover toolbar or connection handles**: there is no hover pop-up, mini-toolbar or connector handles in the editor code. Hover changes only the cursor. (src/ui/diagram-editor.js:167-417) — **UMLCraft:** ✅ present hover changes only the cursor. There is no hover toolbar; the only extra is a target outline while dragging a new line (src/canvas.rs:289-301, 389-404)

## Selection rules

- **Click selects one view**: left-clicking an unselected view replaces the selection with it. (src/ui/diagram-editor.js:652-656, 2656-2663) — **UMLCraft:** ✅ present a click on an unselected view replaces the selection (src/canvas.rs:531-532)
- **Click on an already-selected view keeps the group**: left-pressing a view that is already part of a multi-selection keeps the whole selection, so the group can be dragged. (src/ui/diagram-editor.js:654, 681-695) — **UMLCraft:** ✅ present pressing a selected member keeps the selection and starts a group move (src/canvas.rs:533-536)
- **Click without drag collapses the group**: pressing and releasing on a member of a multi-selection without moving (and without Shift) reduces the selection to that view. (src/ui/diagram-editor.js:901-912) — **UMLCraft:** ❌ missing a release with no movement leaves the multi-selection as it was (src/canvas.rs:766-770)
- **Shift+click toggles**: Shift+left-click on a view adds it if it is unselected and removes it if it is selected. (src/ui/diagram-editor.js:645-651) — **UMLCraft:** ✅ present Shift (or Ctrl) + click toggles membership (src/canvas.rs:514, 523-530)
- **Shift+press never drags**: after a Shift+click the handler is in "additional" mode, and moving the mouse does not move anything. (src/ui/diagram-editor.js:659-660, 747-876) — **UMLCraft:** ❌ missing Shift+press still calls start_move, so a Shift-drag moves the selection (src/canvas.rs:523-536)
- **Rubber-band selection**: pressing on empty canvas and dragging draws a selection rectangle, which is clamped at the left and top canvas edge. (src/ui/diagram-editor.js:639-641, 747-765) — **UMLCraft:** 🟡 partial empty-canvas press starts a dashed selection rectangle, but it is not clamped at the left/top edge (src/canvas.rs:516-521, 279-287)
- **Rubber band selects by overlap**: views whose bounding box intersects the band are selected. They do not have to be fully enclosed. An already-selected view gets 5 px of extra margin. (src/core/core.js:4162-4176, 1901-1907; src/core/graphics.js:1011-1018) — **UMLCraft:** 🟡 partial selection needs full enclosure: nodes must lie inside, edges need every point inside. No overlap rule, no 5 px margin (src/canvas.rs:600-613)
- **Rubber band replaces, Shift+band adds**: without Shift, releasing the band first deselects everything. With Shift held at release, the band adds to the existing selection. (src/ui/diagram-editor.js:892-899) — **UMLCraft:** ✅ present without a modifier the press deselects and the band replaces; with Shift/Ctrl it adds to the base selection, updated live (src/canvas.rs:516-520, 615-625)
- **Rubber band reaches nested views**: area selection recurses into subviews and also selects selectable, visible, enabled children that do not inherit style (for example edge labels), but not compartments or name labels. (src/core/core.js:3895-3913, 4176) — **UMLCraft:** ❌ missing only top-level ownedViews are tested; nested views and edge labels are never selected (src/canvas.rs:603)
- **Select All**: Ctrl+A selects every visible, enabled, selectable top-level view and their selectable non-parentStyle descendants. If an `<input>` or `<textarea>` has focus, it selects that field's text instead. (src/engine/default-commands.js:859-868; src/core/core.js:4180-4196) — **UMLCraft:** 🟡 partial Ctrl+A selects every top-level ownedView, including hidden ones, with no descendants. In a text field the shortcut is skipped, so the field's own select-all works (src/canvas.rs:991-996; src/ui.rs:908, 928-930, 940-942)
- **Click on empty canvas clears the selection**: a plain click on empty canvas is a zero-size rubber band, so it deselects all. (src/ui/diagram-editor.js:639-641, 892-899) — **UMLCraft:** ✅ present a plain press on empty canvas clears the selection (src/canvas.rs:516-519)
- **Canvas and explorer selection are linked**: selecting views selects their models, and clears the explorer selection. An empty canvas selection clears both. (src/app-context.js:1325-1337, 1061-1069; src/engine/selection-manager.js:105-121) — **UMLCraft:** ✅ present selecting views sets the explorer focus to the model, an empty selection clears it, and clicking in the explorer selects the model's view in the current diagram (src/app.rs:615-630)
- **Tab cycles through views**: Tab selects the next top-level view in the diagram's `ownedViews` order. It wraps to the first view and starts from the first if nothing is selected. There is no Shift+Tab reverse, and the browser focus change is suppressed. (src/ui/diagram-manager.js:726-754) — **UMLCraft:** ❌ missing Tab is not handled on the canvas (src/canvas.rs:431-473)
- **Bug: rubber-band Y clamp**: when the band passes the bottom limit, the code assigns the limit to `f2.x` instead of `f2.y`. The upper limit is actually undefined, see the next bullet. (src/ui/diagram-editor.js:761-763) — **UMLCraft:** ➖ n/a upstream bug. UMLCraft does not clamp the band at all (src/canvas.rs:598-600)
- **Coordinates clamp only at 0**: drag limits use `editor.diagramWidth` and `editor.diagramHeight`, which are never defined. In practice moves, resizes, edge points and bands are clamped only at x ≥ 0 and y ≥ 0, with no upper bound. (src/ui/diagram-editor.js:755-762, 804-820, 1357-1359, 1847-1858; no definition found in src/ or extensions/) — **UMLCraft:** 🟡 partial no upper bound, like the original, but also no clamp at 0: moves, resizes and bend points can go negative (src/canvas.rs:649-652, 688-692, 706)

## Moving nodes

- **Drag to move**: pressing inside a single selected node (not on a handle) and dragging shows a dashed rubber-band preview of the node's box. On release it commits one undoable "move views" operation. (src/ui/diagram-editor.js:1520-1532, 1627-1675; src/engine/engine.js:616-746) — **UMLCraft:** ✅ present press and drag moves the nodes live, not as a dashed preview, after a 3 px threshold. The drag is one undo checkpoint (src/canvas.rs:633-659, 766-770)
- **Move constraints**: a node's `movable` flag can be MM_FREE, MM_HORZ (x only), MM_VERT (y only) or MM_NONE (immovable). The drag preview and the committed move both honour it. (src/ui/diagram-editor.js:1612-1622, 1642-1674) — **UMLCraft:** ❌ missing no movable flag is read; every node moves freely (src/canvas.rs:541-587)
- **Moves snap to the grid**: the left/top of the moved node snaps to grid multiples, subject to the small-drag rule above. (src/ui/diagram-editor.js:1287-1323) — **UMLCraft:** 🟡 partial the lead node's left/top snaps to the grid, but without the small-drag rule (src/canvas.rs:643-647)
- **Contained views move with their container**: moving a container also moves every view in its `containedViews`, recursively, including views contained in its subviews. (src/engine/engine.js:633-654) — **UMLCraft:** 🟡 partial only one level of containedViews follows, plus nodes geometrically inside a Package/Subject view. Not recursive (src/canvas.rs:549-573)
- **Edges between moved nodes move rigidly**: an edge whose head and tail are both being moved, or a self-loop on a moved node, is translated as a whole, bend points included. Other edges attached to moved nodes are re-routed and recorded in the same undo step. (src/engine/engine.js:655-702) — **UMLCraft:** ✅ present edges with both ends moved and more than 2 points are translated rigidly. Other attached edges are re-routed by layout in the same undo snapshot (src/canvas.rs:575-585, 653-658; src/views.rs:793-843)
- **Container resizes when its children move**: moving contained views also records the container's state, since containers recompute their size. (src/engine/engine.js:703-709) — **UMLCraft:** ❌ missing no container model, so containers never resize for their children (src/views.rs:737-748)
- **Multi-selection drag**: dragging any member of a multi-selection shows one rubber band around the union bounding box. The delta is grid-snapped and clamped at the canvas origin. On release all selected views move by the same delta. (src/ui/diagram-editor.js:681-695, 768-826, 914-931) — **UMLCraft:** 🟡 partial all selected nodes move by the same snapped delta, live (no union rubber band), and the delta is not clamped at the origin (src/canvas.rs:633-659)
- **Arrow keys nudge by 1 px**: Up/Down/Left/Right moves all selected views by 1 px through the normal move operation, so it is undoable and contained views follow. The page does not scroll. (src/ui/diagram-manager.js:755-814) — **UMLCraft:** 🟡 partial arrows nudge by 1 px as one undo step, but only while the canvas has focus, and contained views don't follow (src/canvas.rs:457-472)
- **Shift+arrow nudges by one grid step**: with Shift, the nudge is the current grid factor (`gridSize`, or 1 if snap is off). (src/ui/diagram-manager.js:761-765, 776-780, 791-795, 806-810) — **UMLCraft:** 🟡 partial Shift+arrow always uses GRID_SIZE (8), even with snap off, where the original uses 1 (src/canvas.rs:459)

## Resizing nodes

- **Eight resize handles**: a single selected free-sizable node can be resized from 4 corners and 4 edge midpoints, with a rubber-band preview. Release commits a "resize node" operation that also re-routes connected edges and their labels. (src/ui/diagram-editor.js:1411-1454, 1548-1609, 1677; src/engine/engine.js:797-886) — **UMLCraft:** ✅ present 8 handles on a single selected node. The resize is live (no preview), one undo step, and edges are re-routed by layout (src/canvas.rs:492-495, 660-693; src/views.rs:793)
- **Sizable modes**: SZ_FREE and SZ_RATIO get all 8 handles, SZ_HORZ only left and right, SZ_VERT only top and bottom, and SZ_NONE none. (src/ui/diagram-editor.js:1411-1454) — **UMLCraft:** ❌ missing all nodes get all 8 handles; there are no sizable modes (src/canvas.rs:150-160)
- **Ratio is not enforced while dragging**: for SZ_RATIO nodes the aspect ratio is computed, but the resize code never applies it. They resize like free nodes in the manipulator. (src/ui/diagram-editor.js:1388-1390, 1548-1556) — **UMLCraft:** ➖ n/a upstream quirk. UMLCraft has no SZ_RATIO nodes, so everything resizes freely (src/canvas.rs:660-693)
- **Minimum size**: a resize cannot make the node smaller than its `minWidth`/`minHeight`. The opposite edge stays anchored. (src/ui/diagram-editor.js:1455-1493, 1201-1285) — **UMLCraft:** 🟡 partial a 20 px floor keeps the opposite edge anchored. Below the content minimum, layout's grow() pushes width/height back out to the right/bottom, so a left/top drag moves the far edge (src/canvas.rs:677-682; src/views.rs:602-607)
- **Resized edges snap to the grid**: the dragged edge or edges snap to grid multiples, subject to the small-drag rule. (src/ui/diagram-editor.js:1201-1285) — **UMLCraft:** 🟡 partial the dragged edges snap to the grid, but without the small-drag rule (src/canvas.rs:665-676)
- **Auto-resize disables manual resizing**: with `autoResize` on, the node shows no resize cursors and cannot be resized by dragging. Its size is forced to its computed minimum (content) size on every layout. (src/ui/diagram-editor.js:195, 1365-1369; src/core/core.js:2115-2125) — **UMLCraft:** ❌ missing autoResize is defined in meta but never read; nodes only grow to their content minimum (src/meta.rs:43; src/views.rs:602-607)
- **Format > Auto Resize toggle**: if all selected views have the same value it is inverted. If the values are mixed, they all become `true`. (src/engine/default-commands.js:1013-1017; src/core/core.js:1058-1078) — **UMLCraft:** ❌ missing no Auto Resize command (src/ui.rs:831-846)
- **Labels resize horizontally only**: node and edge labels are SZ_HORZ, so you can widen them, which matters with word wrap. With word wrap on, text wraps to the label width, and the minimum width is the widest single word. (src/core/core.js:3705-3727, 3769-3790) — **UMLCraft:** ❌ missing labels cannot be selected or resized; word wrap exists only for notes/text drawing (src/render.rs:102-131)

## Containment (drop into packages, boundaries, frames…)

- **Live container highlight**: while dragging a single node whose `containerChangeable` flag is set (not when resizing), the view under the cursor is outlined as the prospective container if it can hold this view kind and its model can contain the dragged model.
