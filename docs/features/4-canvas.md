# Diagram canvas and editing

Part of the [StarUML feature inventory](README.md); the legend and how to update a status are there.

Source: the extracted `app/` tree. Paths below are relative to `app/`. Each bullet is a behaviour found in the code. Where something looks like a bug or quirk, it says so, because a parity port has to decide whether to copy it.

## Mouse buttons and modifiers (canvas-level dispatch)

- **Left button goes to the active tool**: a left press, move or release without Ctrl/Cmd goes to the active handler (the Select tool or a create tool). (src/ui/diagram-editor.js:2190) — **UMLCraft:** ✅ present a left press with no tool goes to selection, with a tool to node/edge creation (src/canvas.rs:650, 837)
- **Ctrl/Cmd + left-drag pans**: holding Ctrl (or Cmd/Meta) while left-dragging moves the viewport. The cursor becomes `move`, and the delta is divided by the zoom scale so the content follows the pointer. (src/ui/diagram-editor.js:2178, 2236-2244) — **UMLCraft:** ✅ present Ctrl/Cmd+left-drag pans with the move cursor; the delta is divided by the zoom and clamped at 0 (src/canvas.rs:833-836, 1018-1021, 674-676)
- **Ctrl/Cmd blocks all editing**: while Ctrl or Meta is held, press, move and release never reach the tool. Ctrl+click does not select, and Ctrl+drag never moves views. (src/ui/diagram-editor.js:2178-2193, 2208-2220) — **UMLCraft:** ✅ present a Ctrl/Cmd press always pans, before tools, handles and selection, so Ctrl+click never selects and Ctrl+drag never moves views (src/canvas.rs:831-836)
- **Middle-button drag pans**: pressing the middle button and dragging pans the same way as Ctrl+drag. The cursor resets on release. (src/ui/diagram-editor.js:2185-2189, 2245-2251, 2213-2217) — **UMLCraft:** ✅ present middle-button drag pans, delta divided by zoom, clamped at 0, with the move cursor while dragging (src/canvas.rs:660-663, 1018-1021, 674-676)
- **Right-click on empty canvas**: deselects everything (it also runs a zero-size area selection at the point). (src/ui/diagram-editor.js:701-704) — **UMLCraft:** ✅ present a right-click on empty canvas deselects everything and opens the empty-canvas menu (src/canvas.rs:726-737)
- **Right-click on an unselected view**: selects only that view, so the context menu targets it. (src/ui/diagram-editor.js:705-707) — **UMLCraft:** ✅ present selects only that view before the context menu (src/canvas.rs:731-734)
- **Right-click on a selected view**: keeps the whole current selection, so the context menu applies to the multi-selection. (src/ui/diagram-editor.js:705-708) — **UMLCraft:** ✅ present the selection is kept if the view is already in it (src/canvas.rs:732)
- **Alt is ignored**: Alt is captured in the event object but no handler reads it. (src/ui/diagram-editor.js:86-96) — **UMLCraft:** ✅ present no canvas handler reads Alt (src/canvas.rs:606, 902)
- **Every mouse-up emits a canvas "mouseDown" event**: the editor emits its `mouseDown` event on mouse-up, and the app closes any open quick edit in response. Any click on the canvas therefore dismisses the popup. (src/ui/diagram-editor.js:2221; src/app-context.js:1318-1324) — **UMLCraft:** ✅ present every primary press on the canvas commits and closes the inline editor first. It happens on press, not release (src/canvas.rs:650-658)
- **Selection change focuses the canvas**: whenever the canvas selection changes, the `<canvas>` element gets keyboard focus, so canvas keys work straight away. (src/ui/diagram-manager.js:657-660) — **UMLCraft:** ✅ present a changed canvas selection gives the canvas the keyboard, unless it came from the explorer (whose clicks also select the element's view and keep the keyboard for its arrow keys) or a text field is in use (src/canvas.rs:537-546)

## Wheel, zoom and scrolling

- **Wheel scrolls**: a plain wheel event moves the origin by (−deltaX, −deltaY) in raw pixels, not divided by zoom. Two-axis trackpads pan freely. (src/ui/diagram-editor.js:2284-2287) — **UMLCraft:** ✅ present the wheel and two-axis trackpads scroll by their delta as it is, in diagram units, so a step covers more of the screen when zoomed in (src/canvas.rs:645-647, 815-822)
- **Shift+wheel scrolls horizontally**: with Shift held and no horizontal delta, the vertical delta is applied to X. The code comment says this is for non-macOS. (src/ui/diagram-editor.js:2281-2283) — **UMLCraft:** ✅ present with Shift the vertical delta goes to X (src/canvas.rs:819)
- **Ctrl/Cmd+wheel zooms**: each wheel event changes the zoom by ±0.1. Wheel down zooms out and wheel up zooms in. The default browser zoom is prevented. The zoom anchor is the origin, not the cursor or the screen centre. (src/ui/diagram-editor.js:2273-2280) — **UMLCraft:** ✅ present Ctrl/Cmd+wheel steps zoom by ±0.1. The scroll origin (top-left) stays fixed, the same anchor as the original (src/canvas.rs:642-644; src/app.rs:1991-1993)
- **Zoom limits**: the zoom scale is clamped to 0.1–3.0. (src/ui/diagram-editor.js:2396-2406) — **UMLCraft:** ✅ present clamped to 0.1–3.0 (src/app.rs:10-11, 1992)
- **Zoom In/Out commands keep the screen centre**: View > Zoom In/Out changes the zoom by ±0.1 and then re-centres on the point that was at the screen centre. (src/engine/default-commands.js:1063-1077) — **UMLCraft:** ✅ present the menu, toolbar and Ctrl+=/- step by ±0.1 and re-centre on the diagram point that was at the screen centre, clamped at 0 (src/canvas.rs:2319-2328; src/ui.rs:1616-1617, 1950-1955, 2437-2442)
- **Actual Size**: sets the zoom to 1.0 and keeps the current screen centre. (src/engine/default-commands.js:1079-1084) — **UMLCraft:** ✅ present zoom 1.0, keeping the screen centre (src/canvas.rs:2319-2328; src/ui.rs:1956-1958, 2443-2463)
- **Fit to Window**: zoom = min(viewport width / diagram bounding-box width, viewport height / diagram bounding-box height), capped at 1.0 so it never zooms in. It then centres on the diagram's bounding box. (src/engine/default-commands.js:1086-1101) — **UMLCraft:** ✅ present zoom = min(width / box width, height / box height) of the diagram's bounding box, capped at 1.0 and rounded down to a tenth (UMLCraft zooms in whole tenths), then centred on the box (src/canvas.rs:2331-2342)
- **Zoom shown in the status bar**: every zoom change updates the status-bar zoom readout. (src/app-context.js:1467-1473) — **UMLCraft:** ✅ present the status bar shows the zoom % every frame (src/ui.rs:1634)
- **No scrolling into negative space**: the origin is clamped to ≤ 0 on both axes, so you cannot pan left of or above diagram coordinate (0,0). (src/ui/diagram-editor.js:2380-2383) — **UMLCraft:** ✅ present scroll is clamped at ≥ 0 for wheel, pan and minimap (src/canvas.rs:646-646, 384, 1019-1020)
- **Scroll position remembered per diagram**: the origin is saved on the diagram (`_originX` and `_originY`) at every scroll, and restored when you switch back to that diagram. A diagram that has never been scrolled starts at (0,0). (src/ui/diagram-editor.js:2384-2387; src/ui/diagram-manager.js:218-228, 243) — **UMLCraft:** ✅ present the scroll origin is kept per diagram while the project is open and restored on switching back; a diagram never scrolled starts at (0,0). Like the original's `_originX/Y`, it is not saved in the file (src/app.rs:1721-1727, 1749)
- **Scroll-to-view centring**: "select in diagram" centres the viewport on the view's bounding-box centre, taking zoom into account and clamping at 0. (src/ui/diagram-manager.js:340-348, 484-490) — **UMLCraft:** ✅ present Select In Diagram and the --select start-up option centre the canvas on the view's bounding box once the canvas size is known, taking zoom into account and clamping at 0 (src/app.rs:1898-1903, 1906, 2006; src/canvas.rs:405-422, 2301-2305). A plain explorer click still selects the view without scrolling (src/app.rs:1927)
- **Canvas fills the diagram area, HiDPI aware**: the canvas is resized to `#diagram-area` whenever the window resizes, with a backing store scaled by `devicePixelRatio`. It is a viewport, not a fixed-size page. (src/ui/diagram-editor.js:2295-2297, 2318-2333) — **UMLCraft:** ✅ present the canvas is the central panel's max_rect, and egui handles pixels-per-point/HiDPI (src/canvas.rs:388-391)

## Grid and snapping

- **Grid defaults**: the default grid size is 8 px, and both show-grid and snap are on. The real values come from the preferences `diagramEditor.gridSize`, `diagramEditor.showGrid` and `diagramEditor.snapToGrid`, read at start-up. (src/ui/diagram-editor.js:2146-2152; src/ui/diagram-manager.js:837-849) — **UMLCraft:** ✅ present grid 8, show-grid and snap on, read from diagramEditor.gridSize, showGrid and snapToGrid in the preferences file (src/prefs.rs:209-327)
- **Grid lines every two cells**: the visible grid is drawn every `gridSize*2` units, in diagram coordinates so it zooms with the content, with a hairline width of 1/devicePixelRatio. The background and grid colours come from the preferences `diagramEditor.backgroundColor` and `diagramEditor.gridColor`. (src/ui/diagram-editor.js:2499-2538) — **UMLCraft:** ✅ present lines every 2×grid size in diagram coordinates, 1 px, in the grid colour on the background colour from the preferences (src/canvas.rs:447-468)
- **Snap off means a 1-px grid**: turning snap off sets the grid factor to 1×1, so every grid-fitting operation becomes a no-op. Turning it on restores `gridSize`. (src/ui/diagram-editor.js:2304-2316) — **UMLCraft:** ✅ present with snap off, coordinates only round to whole pixels (src/canvas.rs:342-357)
- **Changing grid size takes effect live**: changing the `diagramEditor.gridSize` preference immediately updates the snap factor and repaints. (src/ui/diagram-manager.js:827-831) — **UMLCraft:** ✅ present changing Grid Size in Preferences updates snapping and the grid lines at once (src/prefs.rs:324-327; src/canvas.rs:343, 454)
- **Show Grid / Snap to Grid persist**: both toggles write to preferences, so they survive restarts, and they update the menu check marks. (src/ui/diagram-manager.js:426-462; src/engine/default-commands.js:1103-1115) — **UMLCraft:** ✅ present View menu checkboxes and Ctrl+G / Ctrl+Shift+G toggle them, the check marks follow, and both are kept in the preferences file across restarts (src/prefs.rs:77-158)
- **Small drags do not jump to the grid**: when moving or resizing, a coordinate that stays between its original value and the next grid line keeps the original (unsnapped) value. Only once it crosses into another grid cell does it snap to a grid multiple. An off-grid element therefore stays put on tiny drags. (src/ui/diagram-editor.js:1201-1323, 1892-1915) — **UMLCraft:** ✅ present a moved or resized coordinate keeps its original value while it stays in the grid cell it started in, and snaps once it crosses into another; bend points still snap directly (src/canvas.rs:347-357, 1075-1076, 1105-1114)

## Hit-testing and hover feedback

- **Topmost view wins**: hit-testing sorts the diagram's top-level views by `selectZIndex` and tests from the top down. Inside a view it recurses into subviews from last to first and returns the deepest selectable view under the point. (src/core/core.js:4049-4080, 1794-1807) — **UMLCraft:** 🟡 partial top-level ownedViews are tested from last to first; inside a box only its compartment items are returned on their own (src/canvas.rs:1003-1005), other sub-views (labels, regions, operands) still give the top-level view
- **Non-selectable parts pass clicks to the parent**: views with `selectable = SK_NO` are skipped, which is the default for plain LabelView. Clicking a label therefore picks its owner. (src/core/core.js:3435-3440, 1794-1806) — **UMLCraft:** ✅ present node labels pick their owner because only top-level views are tested; a click on a line's label selects the line (and can drag the label), and a double-click on it opens the line's edit (src/canvas.rs:259-275, 892-900, 698-701)
- **The selected view keeps priority**: if exactly one view is selected and you press inside its selection-handle zone (outside its bounding box but still "containing" the point), or anywhere on a selected edge, that view is the target even if another view lies underneath. Overlapping views do not steal handle grabs. (src/ui/diagram-editor.js:556-585, 629-636) — **UMLCraft:** ✅ present for a single selected node, handles are tested before hit_view. For a single selected edge, its points and segments are tested first (src/canvas.rs:845-889)
- **Resize handle size**: handles are 8×8 screen pixels (half-size 4), centred 4 px outside each corner and edge midpoint of the node's zoomed bounding box. (src/core/graphics.js:2726-2727; src/ui/diagram-editor.js:204-299) — **UMLCraft:** ✅ present handles are drawn 8×8 and centred 4 screen px outside the corners and edge midpoints; the hit zone is ±6 screen px around them (src/render.rs:15, 932-938; src/canvas.rs:337-339, 502-505)
- **Hover cursor on node handles**: with exactly one node selected, hovering a handle shows nwse-resize (top-left and bottom-right), nesw-resize (top-right and bottom-left), ns-resize (top and bottom middle) or ew-resize (left and right middle). Elsewhere the cursor is the default. (src/ui/diagram-editor.js:183-327) — **UMLCraft:** ✅ present nwse/nesw/ns/ew resize cursors on the 8 handles when exactly one node is selected (src/canvas.rs:677-692)
- **Hover cursors respect sizability**: free-sizable and ratio nodes show corner and middle handles. Horizontal-only nodes show only the left and right handles, vertical-only nodes only top and bottom. Non-sizable or auto-resize nodes show no resize cursors. (src/ui/diagram-editor.js:195-300) — **UMLCraft:** ✅ present only the handles a view's sizable mode allows are drawn and take the resize cursors, none on an auto-resized box (src/canvas.rs:421-433, 594-603; src/views.rs:2843-2888)
- **Hover cursor on edge endpoints**: with exactly one edge selected, hovering its first or last point shows the `pointer` (hand) cursor, meaning it can be reconnected. (src/ui/diagram-editor.js:396-401) — **UMLCraft:** ✅ present with one line selected, its first and last points show the hand cursor (src/canvas.rs:297-307)
- **Hover cursor on bend points**: hovering an intermediate point of an edge with more than 2 points shows the `move` cursor. (src/ui/diagram-editor.js:377-403) — **UMLCraft:** ✅ present intermediate points of the selected line show the move cursor (src/canvas.rs:308-310)
- **Hover cursor on segments**: within 4 px of a segment, a rectilinear or rounded-rectilinear edge shows ns-resize on horizontal segments and ew-resize on vertical ones. Oblique and curve edges show `crosshair`. (src/ui/diagram-editor.js:344-411) — **UMLCraft:** ✅ present within 4 px of a segment: ns-resize on horizontal and ew-resize on vertical segments of rectilinear lines, crosshair on oblique and curve lines (src/canvas.rs:311-319)
- **No hover feedback with multiple or zero selections**: the hover cursor logic runs only when exactly one view is selected. (src/ui/diagram-editor.js:169-172) — **UMLCraft:** ✅ present handle cursors only appear when selection.len()==1 (src/canvas.rs:328)
- **No hover toolbar or connection handles**: there is no hover pop-up, mini-toolbar or connector handles in the editor code. Hover changes only the cursor. (src/ui/diagram-editor.js:167-417) — **UMLCraft:** ✅ present hover changes only the cursor. There is no hover toolbar; the only extra is a target outline while dragging a new line (src/canvas.rs:528-540, 677-692)

## Selection rules

- **Click selects one view**: left-clicking an unselected view replaces the selection with it. (src/ui/diagram-editor.js:652-656, 2656-2663) — **UMLCraft:** ✅ present a click on an unselected view replaces the selection (src/canvas.rs:920-924)
- **Click on an already-selected view keeps the group**: left-pressing a view that is already part of a multi-selection keeps the whole selection, so the group can be dragged. (src/ui/diagram-editor.js:654, 681-695) — **UMLCraft:** ✅ present pressing a selected member keeps the selection and starts a group move (src/canvas.rs:925-928)
- **Click without drag collapses the group**: pressing and releasing on a member of a multi-selection without moving (and without Shift) reduces the selection to that view. (src/ui/diagram-editor.js:901-912) — **UMLCraft:** ✅ present pressing a member of a multi-selection and releasing without moving keeps only that view (src/canvas.rs:922-929, 1349-1354)
- **Shift+click toggles**: Shift+left-click on a view adds it if it is unselected and removes it if it is selected. (src/ui/diagram-editor.js:645-651) — **UMLCraft:** ✅ present Shift+click toggles membership (src/canvas.rs:902, 910-920)
- **Shift+press never drags**: after a Shift+click the handler is in "additional" mode, and moving the mouse does not move anything. (src/ui/diagram-editor.js:659-660, 747-876) — **UMLCraft:** ✅ present a Shift press on a view only toggles it and starts no move (src/canvas.rs:910-920)
- **Rubber-band selection**: pressing on empty canvas and dragging draws a selection rectangle, which is clamped at the left and top canvas edge. (src/ui/diagram-editor.js:639-641, 747-765) — **UMLCraft:** ✅ present an empty-canvas press starts a dashed selection rectangle, clamped at the left and top edge (src/canvas.rs:1024-1026, 518-527)
- **Rubber band selects by overlap**: views whose bounding box intersects the band are selected. They do not have to be fully enclosed. An already-selected view gets 5 px of extra margin. (src/core/core.js:4162-4176, 1901-1907; src/core/graphics.js:1011-1018) — **UMLCraft:** ✅ present visible views whose bounding box intersects the band are selected; an already-selected view counts 5 px larger (src/canvas.rs:1027-1045, 142-144)
- **Rubber band replaces, Shift+band adds**: without Shift, releasing the band first deselects everything. With Shift held at release, the band adds to the existing selection. (src/ui/diagram-editor.js:892-899) — **UMLCraft:** ✅ present without Shift the press deselects and the band replaces; with Shift it adds to the base selection, updated live (src/canvas.rs:902-908, 1045-1052)
- **Rubber band reaches nested views**: area selection recurses into subviews and also selects selectable, visible, enabled children that do not inherit style (for example edge labels), but not compartments or name labels. (src/core/core.js:3895-3913, 4176) — **UMLCraft:** ✅ present the band also selects the visible, enabled labels of each view that do not inherit its style (line labels and floating box labels), but not compartments or name labels (src/canvas.rs:369-384, 1180-1185)
- **Select All**: Ctrl+A selects every visible, enabled, selectable top-level view and their selectable non-parentStyle descendants. If an `<input>` or `<textarea>` has focus, it selects that field's text instead. (src/engine/default-commands.js:859-868; src/core/core.js:4180-4196) — **UMLCraft:** ✅ present Ctrl+A selects every visible, enabled top-level view and their labels that do not inherit their style. In a text field the shortcut is skipped, so the field's own select-all works (src/canvas.rs:2780-2794; src/keymap.rs:142-147; src/ui.rs:2799-2810)
- **Click on empty canvas clears the selection**: a plain click on empty canvas is a zero-size rubber band, so it deselects all. (src/ui/diagram-editor.js:639-641, 892-899) — **UMLCraft:** ✅ present a plain press on empty canvas clears the selection (src/canvas.rs:904-907)
- **Canvas and explorer selection are linked**: selecting views selects their models, and clears the explorer selection. An empty canvas selection clears both. (src/app-context.js:1325-1337, 1061-1069; src/engine/selection-manager.js:105-121) — **UMLCraft:** ✅ present selecting views sets the explorer focus to the model, an empty selection clears it, and clicking in the explorer selects the model's view in the current diagram (src/app.rs:1824-1931)
- **Tab cycles through views**: Tab selects the next top-level view in the diagram's `ownedViews` order. It wraps to the first view and starts from the first if nothing is selected. There is no Shift+Tab reverse, and the browser focus change is suppressed. (src/ui/diagram-manager.js:726-754) — **UMLCraft:** ✅ present while the canvas has focus, Tab selects the top-level view after the first selected one in ownedViews order, wrapping, or the first view when nothing is selected. Shift+Tab does the same. The canvas keeps Tab instead of moving the keyboard focus (src/canvas.rs:742-748, 2281-2294)
- **Bug: rubber-band Y clamp**: when the band passes the bottom limit, the code assigns the limit to `f2.x` instead of `f2.y`. The upper limit is actually undefined, see the next bullet. (src/ui/diagram-editor.js:761-763) — **UMLCraft:** ➖ n/a upstream bug. UMLCraft does not clamp the band at all (src/canvas.rs:1023-1027)
- **Coordinates clamp only at 0**: drag limits use `editor.diagramWidth` and `editor.diagramHeight`, which are never defined. In practice moves, resizes, edge points and bands are clamped only at x ≥ 0 and y ≥ 0, with no upper bound. (src/ui/diagram-editor.js:755-762, 804-820, 1357-1359, 1847-1858; no definition found in src/ or extensions/) — **UMLCraft:** ✅ present no upper bound, like the original; moves (single or group), resizes and bend points stop at 0 (src/canvas.rs:1079-1085, 1116-1118, 1148)

## Moving nodes

- **Drag to move**: pressing inside a single selected node (not on a handle) and dragging shows a dashed rubber-band preview of the node's box. On release it commits one undoable "move views" operation. (src/ui/diagram-editor.js:1520-1532, 1627-1675; src/engine/engine.js:616-746) — **UMLCraft:** ✅ present press and drag moves the nodes live, not as a dashed preview, after a 3 px threshold. The drag is one undo checkpoint (src/canvas.rs:1063-1098, 1355-1376)
- **Move constraints**: a node's `movable` flag can be MM_FREE, MM_HORZ (x only), MM_VERT (y only) or MM_NONE (immovable). The drag preview and the committed move both honour it. (src/ui/diagram-editor.js:1612-1622, 1642-1674) — **UMLCraft:** ✅ present lifelines and time ticks move only across, timing lifelines, states and state invariants only down, compartment items, activations, line parts, regions and operands not at all, by mouse and by arrow keys (src/canvas.rs:900-904, 1186-1191; src/views.rs:2867-2876)
- **Moves snap to the grid**: the left/top of the moved node snaps to grid multiples, subject to the small-drag rule above. (src/ui/diagram-editor.js:1287-1323) — **UMLCraft:** ✅ present the lead node's left/top snaps to the grid, with the small-drag rule (src/canvas.rs:1073-1077)
- **Contained views move with their container**: moving a container also moves every view in its `containedViews`, recursively, including views contained in its subviews. (src/engine/engine.js:633-654) — **UMLCraft:** ✅ present every view in containedViews follows, recursively, plus nodes geometrically inside a Package/Subject view (src/canvas.rs:970-996)
- **Edges between moved nodes move rigidly**: an edge whose head and tail are both being moved, or a self-loop on a moved node, is translated as a whole, bend points included. Other edges attached to moved nodes are re-routed and recorded in the same undo step. (src/engine/engine.js:655-702) — **UMLCraft:** ✅ present edges with both ends moved and more than 2 points are translated rigidly. Other attached edges are re-routed by layout in the same undo snapshot (src/canvas.rs:997-1010, 1092-1097; src/views.rs:1843-1893)
- **Container resizes when its children move**: moving contained views also records the container's state, since containers recompute their size. (src/engine/engine.js:703-709) — **UMLCraft:** ✅ present each layout grows a UML box over its contained views that have `containerExtending` set, plus the compartment padding; like the original, no view sets it by default, and the move is one undo step with the container (src/views.rs:2814-2833)
- **Multi-selection drag**: dragging any member of a multi-selection shows one rubber band around the union bounding box. The delta is grid-snapped and clamped at the canvas origin. On release all selected views move by the same delta. (src/ui/diagram-editor.js:681-695, 768-826, 914-931) — **UMLCraft:** ✅ present all selected nodes move by the same snapped delta, live as single drags do, with one dashed band around the union of the selected boxes, and the group stops at the canvas origin (src/canvas.rs:673-687, 1206-1240)
- **Arrow keys nudge by 1 px**: Up/Down/Left/Right moves all selected views by 1 px through the normal move operation, so it is undoable and contained views follow. The page does not scroll. (src/ui/diagram-manager.js:755-814) — **UMLCraft:** ✅ present arrows nudge the selected boxes by 1 px as one undo step, and contained views follow their box while the canvas has the keyboard, as the original handles them on its canvas element, which a canvas selection focuses (src/canvas.rs:915-925, 933-962)
- **Shift+arrow nudges by one grid step**: with Shift, the nudge is the current grid factor (`gridSize`, or 1 if snap is off). (src/ui/diagram-manager.js:761-765, 776-780, 791-795, 806-810) — **UMLCraft:** ✅ present Shift+arrow moves by the grid size, or 1 with snap off (src/canvas.rs:776-777)

## Resizing nodes

- **Eight resize handles**: a single selected free-sizable node can be resized from 4 corners and 4 edge midpoints, with a rubber-band preview. Release commits a "resize node" operation that also re-routes connected edges and their labels. (src/ui/diagram-editor.js:1411-1454, 1548-1609, 1677; src/engine/engine.js:797-886) — **UMLCraft:** ✅ present 8 handles on a single selected node. The resize is live (no preview), one undo step, and edges are re-routed by layout (src/canvas.rs:845-848, 1099-1135; src/views.rs:1843)
- **Sizable modes**: SZ_FREE and SZ_RATIO get all 8 handles, SZ_HORZ only left and right, SZ_VERT only top and bottom, and SZ_NONE none. (src/ui/diagram-editor.js:1411-1454) — **UMLCraft:** ✅ present free, horizontal-only, vertical-only and fixed modes, per view type as in the original (ports, pins, endpoints, communication messages, time constraints, switches fixed; time segments, ticks, sliders and labels across; activations, regions, operands and sequence duration constraints down); SZ_RATIO boxes (an avatar) get all 8 handles, resize freely and are squared by their layout, as the original never applies the ratio while dragging (src/views.rs:2932-2950)
- **Ratio is not enforced while dragging**: for SZ_RATIO nodes the aspect ratio is computed, but the resize code never applies it. They resize like free nodes in the manipulator.
