## Editions, licensing and evaluation

- **Standard edition features** — Multi-platform (macOS, Windows, Linux), UML 2.x compliant, ERD, DFD, Flowchart, Mindmap, C4 model, Mermaid support, multiple windows, modern UX, dark and light themes, Retina/High-DPI, model-driven development, code generation and reverse engineering for Java, C, C++, C#, Python, JavaScript, TypeScript, PHP and SQL DDL, open APIs, third-party extensions, model validation, export to HTML docs, automatic updates. (https://docs.staruml.io/) — **UMLCraft:** ➖ n/a edition bundle; UMLCraft has no editions (of the listed items it covers only multi-platform builds, UML class/use case editing and a dark theme)
- **Professional edition features** — Everything in Standard plus SysML, BPMN, UI wireframe, AWS, GCP and Azure architecture diagrams, and code generation / reverse engineering for Ruby, Go, Kotlin, Rust, Dart and Swift. (https://docs.staruml.io/) — **UMLCraft:** ➖ n/a edition bundle; none of the Professional extras exist in UMLCraft

## Projects and files

- **Project file (.mdj)** — A project is the top-level element stored as a single `.mdj` file, usually organized as UMLModels, UMLPackages or UMLSubsystems. (https://docs.staruml.io/user-guide/basic-concepts/) — **UMLCraft:** ✅ present: opens and saves one .mdj project (Project > UMLModel/UMLPackage tree), unknown fields kept verbatim (src/app.rs:242, src/model.rs:155)
- **Model vs view** — A model element can have many view elements in one or several diagrams; renaming the model updates all views. (https://docs.staruml.io/user-guide/basic-concepts/) — **UMLCraft:** ✅ present: several views can reference one model (Explorer drag creates another view); name labels are re-read from the model on every layout, so a rename updates all views (src/canvas.rs:348, src/views.rs:493)
- **Fragments (.mfj)** — Any element (typically UMLPackage/UMLModel/UMLSubsystem) can be exported as a separate `.mfj` fragment file and re-imported into a project. (https://docs.staruml.io/user-guide/basic-concepts/) — **UMLCraft:** ❌ missing: no .mfj fragment export/import
- **Profiles** — UML profiles extend UML for languages, methodologies or domains. (https://docs.staruml.io/user-guide/basic-concepts/) — **UMLCraft:** ❌ missing: no profile support (profile elements in a file are kept, not usable)
- **New project** — `Ctrl+N` / File > New. (https://docs.staruml.io/user-guide/managing-project/) — **UMLCraft:** ✅ present: File > New and Ctrl+N, prompting to save changes (src/ui.rs:773, src/ui.rs:1027)
- **New from template** — File > New From Template: UML Minimal, UML Conventional (Use Case/Analysis/Design/Implementation/Deployment models), 4+1 View Model, Rational (Rose approach), Data Model, AWS/Azure/GCP Architecture, BPMN Business Process Modeling, C4 Model, Wireframe Model. (https://docs.staruml.io/user-guide/managing-project/) — **UMLCraft:** ❌ missing: no New From Template; New always gives Project > Model > Main class diagram (src/model.rs:164)
- **Open project** — `Ctrl+O`; files saved by an older version prompt "Convert" (colors to color variables, so they follow themes) or "Keep Colors". (https://docs.staruml.io/user-guide/managing-project/) — **UMLCraft:** ✅ present: Ctrl+O / File > Open with .mdj filter; the Convert / Keep Colors prompt is V8-only and absent (src/ui.rs:1136)
- **Import StarUML 1 file** — File > Import > StarUML 1 File (.uml). (https://docs.staruml.io/user-guide/managing-project/) — **UMLCraft:** ❌ missing: no StarUML 1 (.uml) import
- **Save / Save As** — `Ctrl+S` / `Ctrl+Shift+S`. (https://docs.staruml.io/user-guide/managing-project/) — **UMLCraft:** ✅ present: Ctrl+S / Ctrl+Shift+S, Save As appends .mdj (src/ui.rs:1033, src/app.rs:284)
- **Close project** — File > Close, prompts to save if modified. (https://docs.staruml.io/user-guide/managing-project/) — **UMLCraft:** ✅ present: File > Close resets to a blank project after the save prompt (src/ui.rs:791, src/app.rs:301)
- **Export fragment** — File > Export > Fragment..., choose the element in Element Picker. (https://docs.staruml.io/user-guide/managing-project/) — **UMLCraft:** ❌ missing: no fragment export
- **Import fragment** — File > Import > Fragment...; fragment is added as a child of the project. (https://docs.staruml.io/user-guide/managing-project/) — **UMLCraft:** ❌ missing: no fragment import
- **Export StarUML V7 file** — File > Export > StarUML V7...; color variables are replaced by their light-theme colors; working project unchanged; reopening asks to convert colors again. (https://docs.staruml.io/user-guide/managing-project/) — **UMLCraft:** ❌ missing [V8]: no "Export StarUML V7" (UMLCraft writes the V7 format natively)
- **Export HTML docs** — File > Export > HTML Docs... exports the project as a set of HTML documents. (https://docs.staruml.io/user-guide/managing-project/) — **UMLCraft:** ❌ missing: no HTML docs export
- **Export XMI 2.1** — File > Export > XMI Export (v2.1); model elements only, no diagrams. (https://docs.staruml.io/user-guide/managing-project/) — **UMLCraft:** ❌ missing: no XMI export
- **Import XMI 2.1** — File > Import > XMI Import (v2.1); elements go in a new model `XMIImported`; diagrams not imported. (https://docs.staruml.io/user-guide/managing-project/) — **UMLCraft:** ❌ missing: no XMI import
- **Apply UML Standard Profile** — Model > Apply Profile > UML Standard Profile (v2). (https://docs.staruml.io/user-guide/managing-project/) — **UMLCraft:** ❌ missing: no Apply Profile command

(https://docs.staruml.io/user-guide/managing-project/) — **UMLCraft:** 🟡 partial [V8]: File > Export Diagram As PNG / SVG of the current diagram only, fixed 10 px margin, transparent PNG at screen DPI scale; no dialog, JPEG, range, background fill, scale or margin options, Export All or clipboard, no Ctrl+Shift+E (src/ui.rs:796, src/render.rs:433)
- **Theme-colored export** — Diagrams are exported with the colors of the current theme (light or dark). (https://docs.staruml.io/user-guide/managing-project/) — **UMLCraft:** ❌ missing [V8]: exports use the saved colours (default black on white); no theme colours (src/render.rs:50)
- **Copy Diagram As Image** — `Ctrl+Shift+C` / Edit > Copy Diagram As Image. (https://docs.staruml.io/user-guide/managing-project/) — **UMLCraft:** ❌ missing: no copy-to-clipboard of a diagram image, no Ctrl+Shift+C
- **Print to PDF** — File > Print to PDF...; range (all/current), page layout (landscape/portrait), page size, show diagram names. (https://docs.staruml.io/user-guide/managing-project/, https://docs.staruml.io/user-guide/user-interface/) — **UMLCraft:** ❌ missing: no Print to PDF

## Diagram editor (canvas)

- **Scrolling** — Mouse wheel vertical, `Shift`+wheel horizontal, middle-button drag, or `Ctrl`(`Cmd`)+left-drag. (https://docs.staruml.io/user-guide/diagram-editor/) — **UMLCraft:** 🟡 partial: wheel, Shift+wheel and middle-button drag scroll; Ctrl+left-drag does not scroll (Ctrl+click toggles selection) (src/canvas.rs:362, src/canvas.rs:381, src/canvas.rs:537)
- **Minimap** — Shows whole diagram and viewport; click to scroll there; toggle `Ctrl+Alt+M`, View > Minimap or toolbar icon. (https://docs.staruml.io/user-guide/diagram-editor/) — **UMLCraft:** 🟡 partial: minimap at the bottom right shows the diagram and viewport, click/drag scrolls there; it cannot be toggled (no Ctrl+Alt+M, menu item or toolbar icon) (src/canvas.rs:313, src/canvas.rs:496)
- **Select mode** — Cursor icon in Toolbox or `Esc`. (https://docs.staruml.io/user-guide/diagram-editor/) — **UMLCraft:** ✅ present: cursor icon at the top of the Toolbox and Esc return to select mode (src/ui.rs:649, src/canvas.rs:465)
- **Selection** — Click; rubber-band drag (elements overlapping the area are selected); `Shift`+click / `Shift`+drag adds to selection; `Ctrl+A` select all. (https://docs.staruml.io/user-guide/diagram-editor/, https://docs.staruml.io/user-guide/editing-elements/) — **UMLCraft:** 🟡 partial: click, Shift/Ctrl+click toggle, Shift+drag adds an area, Ctrl+A; the rubber band selects only elements fully inside the area, not overlapping ones (src/canvas.rs:537, src/canvas.rs:628, src/ui.rs:1072)
- **Nudge** — Arrow keys move selection 1 px; `Shift+Arrow` moves by grid size. (https://docs.staruml.io/user-guide/diagram-editor/) — **UMLCraft:** ✅ present: arrow keys move selected nodes 1 px, Shift+arrow by the 8 px grid size (src/canvas.rs:473)
- **Zoom** — `Ctrl++`, `Ctrl+-`, `Ctrl+0` actual size, `Ctrl+9` fit to window (and center), `Ctrl`/`Cmd`+wheel; zoom level shown in Statusbar. (https://docs.staruml.io/user-guide/diagram-editor/) — **UMLCraft:** ✅ present: Ctrl+= / Ctrl+- / Ctrl+0 keep the screen centre, Ctrl+9 fits the bounding box (never above 100%) and centres it, Ctrl+wheel zooms, zoom % in the status bar (src/ui.rs:1092-1103, src/canvas.rs:1081, src/canvas.rs:1093, src/canvas.rs:363, src/ui.rs:743)

## Editing elements

- **Create from Toolbox** — Select a type, drag the size on the diagram (or connect two elements for relationships); creates both model and view element. (https://docs.staruml.io/user-guide/editing-elements/, https://docs.staruml.io/user-guide/user-interface/) — **UMLCraft:** ✅ present: pick a Toolbox tool, drag a size (click gives a default size) or drag between two elements for a line; creates model and view (src/canvas.rs:753, src/canvas.rs:783, src/app.rs:399)
- **Drag model element onto diagram** — Dragging an element from Explorer onto a diagram creates a view referencing it. (https://docs.staruml.io/user-guide/editing-elements/) — **UMLCraft:** 🟡 partial: dragging a classifier/package/actor/use case from the Explorer creates a view of it; relationships and other kinds cannot be dropped (src/canvas.rs:348, src/ui.rs:202)
- **Add model element in Explorer** — Model > Add > [type] or context menu Add. (https://docs.staruml.io/user-guide/editing-elements/) — **UMLCraft:** 🟡 partial: Explorer context menu Add > Package/Class/Interface/Enumeration/DataType/Actor/Use Case (Model under Project) and features; the Model menu only adds attributes/operations/literals (src/ui.rs:243, src/ui.rs:872)
- **Delete view vs delete from model** — `Delete` removes views only; `Ctrl+Delete` (Delete from Model) removes model elements together with all their views. (https://docs.staruml.io/user-guide/editing-elements/) — **UMLCraft:** ✅ present: Delete removes views (and lines hanging on them), Ctrl+Delete removes the models, their relationships and all their views (src/canvas.rs:942, src/app.rs:551)
- **Select In Explorer** — `Ctrl+E`. (https://docs.staruml.io/user-guide/editing-elements/) — **UMLCraft:** ✅ present: Ctrl+E and Edit / canvas context menu "Select In Explorer" expand and scroll the tree to the element (src/ui.rs:1075, src/canvas.rs:1106)
- **Copy/cut/paste views** — Views can be pasted in the same or other diagrams, only into diagrams; may be restricted by view/diagram type. (https://docs.staruml.io/user-guide/editing-elements/) — **UMLCraft:** 🟡 partial: views copy, cut and paste within and across diagrams of the same type, centred on screen (src/clipboard.rs:91-183, 229-277)
- **Copy/paste model elements** — Copied with all sub-elements; pasted under a model element that can contain it; some elements cannot be copied. (https://docs.staruml.io/user-guide/editing-elements/) — **UMLCraft:** ✅ present: a model is copied with all sub-elements and pasted under an element that can contain it (src/clipboard.rs:108-227)
- **Undo / redo** — `Ctrl+Z` / `Ctrl+Y`. (https://docs.staruml.io/user-guide/editing-elements/) — **UMLCraft:** ✅ present: Ctrl+Z, Ctrl+Y (also Ctrl+Shift+Z), Edit menu, snapshot undo limited to 200 steps (src/ui.rs:1045, src/app.rs:347)
- **Assign stereotype** — Magnifier icon on `stereotype` property opens Element Picker for a defined stereotype, or type a name to assign a temporal (text) stereotype. (https://docs.staruml.io/user-guide/editing-elements/) — **UMLCraft:** 🟡 partial: typing a name into the stereotype property stores a text stereotype; linked stereotypes are shown but there is no Element Picker to choose one (src/ui.rs:437, src/views.rs:320)
- **Constraints** — Model > Add > Constraint, edit `specification`. (https://docs.staruml.io/user-guide/editing-elements/) — **UMLCraft:** ❌ missing: no constraints
- **Tags** — Model > Add > Tag; properties `name`, `kind` (`string`, `reference`, `boolean`, `number`, `hidden` - hidden not shown on views), `value`, `reference`, `checked`, `number`. (https://docs.staruml.io/user-guide/editing-elements/) — **UMLCraft:** ❌ missing: tags cannot be added or edited (existing tags only listed in the Explorer as "name = value") (src/ui.rs:169)
- **Find** — `Ctrl+F` / Model > Find, options Case sensitive and Find in documentation; results in a Bottom Panel. (https://docs.staruml.io/user-guide/editing-elements/) — **UMLCraft:** ❌ missing: no Find (Ctrl+F) or results panel; only the Explorer filter box
